# 离线检索方式探索：多轮流程

> 2026-09-26 起草，同日 owner 裁定 §9 后生效。
> 本文件是这条线的流程权威。每轮结束在 §10 台账追加一段；逐轮的工作产物放在 `exp/offline_search/rounds/rNN/`，最终报告放在 `exp/offline_search/analysis/results.md`。

## 1. 目标与边界

**目标**：在离线条件下，不受现行方法的约束，寻找"给定当前观测，从库里选出可直接下发的动作"的更好方式。以下每个环节都可以推翻重来：

- 查询表示：用哪些信息、分不分模态、降到多少维、怎么降；
- 相似度：cosine、L2，或 token 级、排名级、集合级的相似度；
- 融合：要不要加权、要不要相加，也可以相乘、取最小、级联、Pareto、投票；
- 检索结构：kNN，或轨迹跟踪、贝叶斯滤波、图上游走；
- 置信度：什么信号能说明这次可以直接用；
- 库本身：怎么构造、放哪些条目、每条存什么。

现行的"分模态 + zscore+tanh + 加权求和 + LDA 定权"只是基线之一。

**边界（owner 2026-09-26 裁定）**
- **离线**：不跑闭环。方法评测只用 CPU（`CUDA_VISIBLE_DEVICES=""`，每个 worker 设 `OMP/MKL/OPENBLAS_NUM_THREADS=1`）。
- **GPU 只在两种情况下用，且都要有空闲显存**：
  - 测噪声地板（§4.1）；
  - 训练类方法，越快越好。
- **成本分档**：每个方法都要标出档位。系统主打低成本、敏捷部署，所以同等效果下档位越低越好。
  - **T0 零训练**：只用现成张量和固定运算；
  - **T1 闭式统计**：几秒内算完，例如均值、PCA、白化、LDA；
  - **T2 训练**：可以用 GPU，时间越短越好。
- **外部模型（CLIP、DINO 等）优先级最低**。cache 的目的就是省算力，多带一个模型违背初衷。
- **只能用库里已有的动作**：可以选一条，也可以选几条再合成，但不能调用策略模型。
- **库可以自由构造**：条目、字段和规模都不设限。
- **数据**：owner 裁定不存在数据污染问题，trace 全量都可以用来评测，不切 held-out。
- 不改 `src/` 的老实现，新代码只放在 `exp/offline_search/`。**每个阶段完成就 commit**（owner 2026-09-26 授权，规则见 §8）。

## 2. 角色与分工

**每个阶段的 agent 数是静态常量**（全局规则）。方法数量由协调者每轮自定，靠每个编码 agent 承接不同数量的方法来调节，**编码 agent 的个数本身不变**。

| 阶段 | 执行者 | agent 数（固定） | 模型 |
|---|---|---|---|
| R0 搭底座（只做一次） | 编码 agent：A 抽取查询端，B 抽取库端，C 搭底座与指标，D 测噪声地板，E 写 profile 工具（owner 追加） | 5 | 默认（Opus） |
| 1 构思 | 构思 agent：A「破框」，B「诊断驱动的精进」 | 2 | **fable** |
| 1' 选题 | 协调者（本会话）定下本轮的方法清单，数量自定 | — | — |
| ⏸ **暂停点 1** | 把方法清单交给 owner 过目 | — | — |
| 2 编码 | 编码 agent 并行，每个承接一族方法 | 4 | 默认（Opus） |
| 3 运行 | **协调者亲自跑** | — | — |
| 4 分析 | 本轮分析 agent：横向比较所有方法，给出下一轮建议 | 1 | **fable** |
| 5 决策 | 协调者：精进、淘汰还是换新，写进台账 | — | — |
| ⏸ **暂停点 2** | 本轮结束，进入下一轮之前交 owner | — | — |

- 每轮固定 7 个 agent（2 + 4 + 1）。
  - **每轮的方法数量不限，可多可少（owner 2026-09-26 重申）**，由协调者按构思质量决定。编码 agent 恒为 4 个：方法多就每个 agent 承接几个，方法少就把一个方法的变体或消融拆给多个 agent。4 个 agent 始终都要起。
  - 编码 agent 冒烟没过，用 SendMessage 让**同一个** agent 返工一次；再不过就在台账里记失败，不另起新 agent。
- **两个暂停点**：owner 可以指示跳过所有等待、让协调者自行推进。
- **临时的 fable 咨询**：难题可以单独问，例如 GT 是否成立、指标怎么设计、理论上界。每次 1 个，不扇出。
- **编码 agent 对底座 `harness/` 只读**。发现底座的 bug 就报告，由协调者修，以保证各轮口径一致。

## 4. Ground truth 与指标

### 4.1 `full_inference` 作参照答案

`full_inference` 是教师的一次采样，不是唯一正确的动作。这带来三个问题：采样有随机性，动作可能多峰，离线评测是开环的。

对应的处理：
- **噪声地板**：衡量教师两次采样之间有多远。
  - 第 0 步：inf 组和 cache 组起点是同一个 init，raw_state 逐位相同，噪声独立，可以直接配对。每个模型 × suite 得到 500 对，只用 CPU。
  - 中后段：对抽样的决策，在 GPU 上用记录的输入换 K 组新噪声重采样。显存空闲时就跑。
  - 地板按模型 × suite × 步段给出分布。
- **误差表示**：一律同时报两种，一是按地板归一化后的数，二是绝对误差；另外报"与教师不可区分"的比例，即误差 ≤ 地板中位数。
- **非动作口径的参照**：
  - 相位误差 |Δp|，p = 步号 / 集长；
  - 夹爪符号是否一致；
  - 库内留一整条轨迹（LOEO）的自检。

### 4.2 记分板（每个方法 × 8 格）

| 类别 | 指标 |
|---|---|
| 选得准不准（全覆盖） | 执行段误差：前 5 步 × 7 维，每维除以库动作的标准差，取 RMS。报均值、中位数、"不可区分"比例、夹爪不一致率、相位误差、与 oracle 的差距 |
| 知不知道该不该用 | 按方法自己给的置信度排序，接受前 c 的决策：风险-覆盖曲线、AURC，以及 c = 30 / 50 / 70 / 90% 时的风险 |
| 成本 | 每条库条目的字节数；每次查询的 key 构造 + 检索耗时（CPU 单线程）；成本档 T0 / T1 / T2；训练耗时 |
| 稳定性 | 相对现行方法的 top-1 翻转率；inf 组与 cache 组之间的差 |

- **主指标**：inf 组与 cache 组各自的 AURC 和"不可区分"比例。
- 不写死一个加权总分，由分析 agent 逐格讨论。

### 4.3 固定参照（R0 建好，每轮都附上）

- **B0 现役**：必须复现记录下来的 top-1。
- **B1 LDA 权重**：公式同 B0，只换权重。
- **B2 任务内随机**：下界。
- **B3 oracle**：候选集里 GT 误差最小的那条，也就是 regret 预算。
- **B4 单模态**：只用 v0 / 只用 v1 / 只用 state。
- **F 噪声地板**：见 §4.1。

### 5.2 底座（`exp/offline_search/harness/`，R0 后冻结）

- **方法接口**：

  ```python
  class Method:
      name: str; tier: str                      # "T0" | "T1" | "T2"
      def fit(self, lib, ctx) -> None: ...      # 在库上拟合；构造新库也在这里
      def reset(self, episode) -> None: ...     # 每集开头调用
      def query(self, q) -> Result: ...         # 返回 top-k 库行号、分数、置信度，可选"由库动作合成的动作"
  ```

  - query 按集内时间顺序送入。
  - 有状态的方法只能用线上可得的信息：本集历史的 key、已执行的动作、步号。**集长、成功标记和 GT 不可用。**
- **运行器**：主进程 `fit` 一次，fork 出多进程，按集切分；输出 `results/rNN/<method>/<cell>.npz` 和汇总 json，并更新 `results/scoreboard.csv`。
- **验收门**（R0 必须通过）：
  1. B0 与记录的 top-1 一致率 ≥ 99.9%，不一致的决策分差都 < 1e-4；
  2. B3 的误差 ≤ B0；
  3. B2 的误差明显高于 B0；
  4. 同一方法跑两次结果逐位相同；
  5. current 库重建后的 key 和动作与 pkl 逐位（或 ≤ 1e-6）一致。

### 5.3 精细 profile 工具（`exp/offline_search/profile/`，owner 2026-09-26 追加：运行时不能两眼一抹黑）

底座为这些工具提供的钩子：
- `Result.extras`：方法可以自愿暴露逐决策的内部量；
- 分段计时器：`prof.section(...)`；
- 逐决策的查询耗时；
- `progress.jsonl`：记录每个 worker 的进度、吞吐和 RSS。

| 工具 | 回答的问题 |
|---|---|
| `coverage` | 库是不是瓶颈：每个查询在库里有没有"好候选"（误差 ≤ 地板），oracle 能到多少，按任务 / 步段切开看。结果缓存到 `profile_cache/`，其他工具复用 |
| `explain` | 某一步为什么选了它：top-k、oracle 候选及其名次、top1 与 top2 的差距，以及是哪一路字段把它带偏的 |
| `breakdown` | 在哪里赢、在哪里输：按组、任务、步段、成败集、夹爪切换步、置信度分位、候选数、是否存在好候选分别切片 |
| `compare` | 方法 A 对方法 B：逐决策配对差，胜 / 平 / 负，以集为单位 bootstrap 的 95% CI，分歧最大的决策清单 |
| `timeline` | 单集时间线：每步选中的库轨迹和步号、oracle、相位误差；轨迹跳变率与"沿轨迹前进"率 |
| `repr` | 表示本身好不好：饱和度、有效维数、hubness、key 相似度排名与动作误差排名的一致性、好 / 坏候选的 AUROC。可以接入新的 encode 函数 |
| `runprof` | 时间和内存花在哪：吞吐、worker 均衡、分段耗时 p50 / p95 / p99、fit 耗时、每条库条目的字节数、库规模扩展曲线；`live` 子命令用于查看正在跑的实验 |

分析 agent 和协调者用这些工具做诊断。每轮的分析必须附上 `coverage`、`breakdown` 和 `compare`（对 B0 与上一轮最佳）的结果。

## 6. 每轮流程（第 1–10 轮）

1. **构思**：2 个 fable 构思 agent 并行。
   - 输入：本文件、记分板、上一轮的分析。
   - 每个提案写明：假设、机制、预计会动哪些指标、成本档、实现要点、**淘汰判据**。
   - A 至少要有 2 个提案跳出"分模态加权求和"。
   - B 从上一轮的诊断出发；第 1 轮从 §3.3 和历史负结果出发。
2. **选题**：协调者定下本轮的方法清单，数量不限、可多可少，按实现上的亲缘关系分配给 4 个编码 agent，写进台账。→ **⏸ 暂停点 1**。
3. **编码**：4 个编码 agent 并行（每个承接分到的全部方法），在 `rounds/rNN/fK_<family>/` 下实现方法。
   - 必须用 `harness smoke` 跑通（单格、少量决策、CPU）并通过接口检查。
   - 交回代码摘要和冒烟输出。
4. **运行**：协调者跑全量（所有方法 × 8 格）。
   - 用脚本启动，写出 DONE / ERROR 标记，由 Monitor 按条件触发。
   - 预计超过 30 分钟的，另挂 cron 定时巡检。
5. **分析**：1 个 fable 分析 agent，输出：
   - 每个方法的判决（保留 / 精进 / 淘汰）和理由；
   - 跨方法的发现；
   - 失败案例的画像；
   - 下一轮建议。
6. **决策与记账**：协调者在 §10 追加本轮小结。→ **⏸ 暂停点 2**。

**停止**
- 跑满 10 轮就停。
- 协调者判断应当停止时，也可以提前停。例如方法或指标本身可能有问题、连续几轮没有进展、发现了需要 owner 决策的现象。**停下来说明理由，等 owner 指示。**

**收尾**：给出进入闭环验证的候选（2–3 个）和理由。闭环需要 GPU 和 timan107，另行审批。

## 7. 想法种子池（不约束，只是构思的起点）

- **不分模态**：
  - 把各路白化后拼接，只算一个相似度；
  - 用中间层的单向量；
  - 用原始像素缩略图，完全不用模型。
- **分模态但不相加**：
  - 相乘，或取最小值（要求所有模态同时满意）；
  - 级联：先用 state 粗筛，再用 vision 精排；
  - Pareto 非支配集，或排名投票。
- **消除饱和的根源**：
  - 任务内去均值或白化，再算 cosine（vision 的 cos 都挤在 0.97 ± 0.007）；
  - 按任务单独标定 μ/σ；
  - 局部尺度校正（CSLS / hubness）。
- **降维与压缩**：
  - 任务内 PCA、随机投影、二值码 + Hamming 距离、乘积量化；
  - 按方差选 token、残差 token；
  - token 级 late interaction（MaxSim）。
- **不靠 key 的信号**：
  - 动作块重叠：上一步执行块的尾段应当接上本步块的首段，可以当作零视觉的查询；
  - 步号或相位先验；
  - 状态速度。
- **历史，但不做分数平滑**（分数平滑已证伪）：
  - 沿库轨迹的 `next` 跟踪，再用相似度校验；
  - 以库条目为隐状态，做 HMM 前向滤波。
- **top-k 而不是 top-1**：
  - 对 k 条动作取 medoid 或逐步中位数（多峰时不能取均值）；
  - 用 top-k 动作之间的一致性当置信度；
  - 比率检验：top1 与 top2 的差距。
- **库侧**：
  - 去冗余；
  - 用 B 池余量扩容；
  - 丢掉失败轨迹；
  - 每条多存几种表示。

**已证伪、不再重试**：
- 把深度 d>1 的历史分数加进打分；
- percentile 归一化；
- RRF 作为主融合；
- 在同类数据上训 InfoNCE 投影头；
- 按离线 L2 取 argmin 定权；
- 在 100 集分辨率下加密权重网格；
- 在动作空间把缓存动作和策略输出线性混合。
