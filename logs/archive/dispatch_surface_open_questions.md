## 2. 我做了哪些检验、怎么做的、每项能证明什么

下面每一项都标注**方法**、**结论**，以及我认为**这项检验没能排除的可能**。最后一栏是我请审查者特别留意的地方。

### 2.1 标定表本身是否有问题

- **方法**：对 3364 行逐列统计——`v`/`s`/`y_tau7`/`y_tau10` 的 None 计数、`k_eff` 取值集合、task/episode/split 计数、各列取值范围。
- **结论**：`v_none=0`、`s_none=0`、`k_eff` 恒为 5、10 tasks / 150 episodes（fit 50 + cal 100，与冻结配额一致）、`ref_mode` 全为 fresh。
- **没排除**：这只证明表是**完整**的，不证明 `y` 的**语义**正确。若 `weighted_chunk_deviation` 的权重或 active_mask 有系统性问题，上述检查全都会通过。我没有独立复算过 `y`。

### 2.2 宽度修复是否污染了别的列

（背景：本轮先前发现标定期检索宽度未被抬到 5，首版表 `v` 全空，已作废重跑。）

- **方法**：把作废表当对照组，按 `(episode_id, step_idx)` 全键对齐，逐行比较 `s` / `winner_id` / `y_tau10`。
- **结论**：3364/3364 键对齐；`max|s 差| = 0`、`winner_id` 全同、`max|y_tau10 差| = 0`。宽度只影响 `v` 与 `k_eff`。
- **附带用途**：这同时是"top-1 winner 与检索宽度无关"的实测证据，S0 臂在部署期宽度=1 下的有效性依赖它。
- **没排除**：这是同一份实现内部的一致性，不是对实现正确性的外部验证。

### 2.3 止损是不是算术上被强制的

- **方法**：把 `evaluate_candidate_deployed` 的接受条件 `q̂ + offset ≤ δ` 拆开，与 `y` 的经验分布对比。
- **结论**：

  | 量 | 值 |
  |---|---|
  | δ 网格上界（= p90 of `y10[fit]`） | 6.187 |
  | OOF safety offset | 5.373 |
  | ⇒ 需要 `q̂ ≤` | 0.814 |
  | `y10` 的全局最小值 | 2.655 |
  | `p90(y10) − p10(y10)` | 2.554 **< offset** |

  由于 `p90 − p10 < offset`，网格里不存在任何 δ 能满足接受条件——**哪怕 q̂ 是完美的条件分位数**（其下界仍 ≥ y 的最小值）。
- **没排除**：这解释了"为什么 hitshare 恒为 0"，但**不解释 offset 为何这么大**，也不说明这是否是预期行为。§2.4 才处理前者。

### 2.4 ~~offset 为什么这么大 —— teacher 自噪声~~ 【已失效，见 §7.2】

- **方法**：跑预注册的 `noise_sensitivity`（fit split 分层抽 50 步，每步用**独立、记录种子**的初始噪声重复生成 8 次），测同一观测下 teacher 采样两两之间的偏差 `tt`，与检索 winner 的 τ=7 warm 补全 vs 一次 teacher 采样的偏差 `wt` 对比。度量函数、`W/active_mask`、`h_exec` 与标定表完全一致。
- **结论**：

  | 量 | 中位 | p95 |
  |---|---|---|
  | `tt`（teacher–teacher） | **6.222** | 8.380 |
  | `wt`（cache–teacher） | **3.181** | 6.406 |
  | ratio | **1.956** | |

- **~~一致性佐证~~ —— 这条我写错了，事后读源码更正**：我原先说「`wt` 中位 3.181 与标定表 `y7` 中位 3.31 几乎相等，两者由不同代码路径、不同抽样得到，可作可比性证据」。**这是错的。** `noise_sensitivity.py:112` 是 `wt_devs.append(row["y_tau7"])`——**`wt` 直接取自标定表的 `y_tau7` 列，不是独立计算的**。两者几乎相等近乎恒真，差别只来自 50 步子采样 vs 1134 行。
  **后果**：我原本用来支撑「`tt` 与 `y` 尺度可比」的主要依据消失了。目前**没有**独立证据说明这两个量可比，而 §4.3 的整条解释链依赖这个可比性。请审查者特别注意这一点。
- **另一处措辞不准确的更正**：`tt` 是**两次完整 stage3 采样**（从纯噪声跑满 10 步）之间的偏差；`wt` = `y_tau7` 是**从检索 winner 的中间态做 τ=7 warm 补全**再与一次 teacher 采样比。warm 补全已积分掉 70% 的流、**是方差更低的对象**。所以「cache vs teacher」与「teacher vs teacher」并非同类比较，我此前的表述不准确。
- **我据此形成的解释**：`y` 的地板（全局最小 2.655）看起来不是检索能力的上限，而更像策略自身采样噪声的下限；这条重尾又通过 `episode-max 残差的第 49/50 序统计量` 被整个吸收进 offset。
- **没排除 / 我不确定的地方**：
  - n=50 步、m=8 采样，`tt_median` 的不确定性我没有量化（脚本不输出置信区间）。"δ 上界 6.187 < tt 中位 6.222"这句话，我认为**只能当作"同量级、互相跨过"，不宜当作精确的临界判定**。
  - `tt` 是 pair 间偏差的中位数聚合，`y` 是对 teacher 单次采样比，两者定义不完全同构。`wt ≈ y7` 是支持可比性的证据，但不是证明。

### 2.5 是 offset 的量级、还是曲面本身没有判别力

- **方法**：新写 `exp/dispatch_surface/analysis/characterize_stop_loss.py`（**尚未过 G2**）。它只读地复用 `fit_surface` 自己的 `assign_folds` / `fit_fold_models` / `evaluate_candidate_deployed`，**不写 artifact、不重解阈值、不重跑冻结的 δ 规则**；δ 始终停在冻结网格上，**唯一被扫的是 offset**。
- **结论**：

  | offset | 冻结 δ 网格上的最大 hitshare | 该点 δ / OOF accuracy |
  |---|---|---|
  | 0 | 0.6093 | 6.1875 / 0.9826 |
  | offset/4 = 1.343 | 0.2698 | 6.1875 / 0.9967 |
  | offset/2 = 2.687 | 0 | — |
  | 5.373（实际） | 0 | — |

  冻结门为 `acc_gate = 1 − α − ACCURACY_SLACK = 0.90`、`HITSHARE_TARGET = 0.40`。offset=0 时有两档 δ 同时越过两道门（5.5331→0.4912、6.1875→0.6093，acc 均 ≈0.985）。
- **我据此形成的解释**：把 hitshare 压到 0 的看起来是 offset 的量级，而不是曲面的判别力，也不是偏差地板本身。
- **必须钉住的边界（我担心这张表被误读）**：
  - **offset=0 一栏不是方案、不是替代拟合、也不是"其实能work"的证据。** offset 的存在正是为了让 δ 不被 in-fold 过拟合；去掉它就没有任何跨 fold 的安全保证。
  - 表里的 acc 虽是 OOF 的（每折 held-out 行上判），但那是**逐步**精度，不是 episode 级证书，也不等于部署期的 split-conformal `c`。
  - **这些反事实是我看了失败数据之后才算的。** 它们作为归因证据我认为成立；作为改规则的依据，可信度问题见 §5。

### 2.6 (A1) 双单调假设是否成立

- **方法**：Spearman 相关 + 按 s 十分位的中位 `y10`。
- **结论**：`Spearman(y10, s) = −0.328`、`Spearman(y10, v) = +0.304`，符号均与 (A1) 一致；s 十分位的中位 `y10` 从 5.35 单调降到 3.97，p95 同向 7.79 → 5.38。
- **我的读法**：(A1) 在数据上站得住，**这次失败不宜读成"曲面没有预测力"**。

### 2.7 `v` 相对 `s` 是否有增量信息（决定 SV 能否超过阈值前沿）

- **动机**：T1–T3 是 `s` 上的率切；S0 虽按偏差标定，但在 s 的单调变换上与率切同族，落点正是 (f_FH, f_WS) 网格在扫的。**因此 SV 相对阈值前沿的结构性优势看起来只剩 `v`。** 若 `v` 被 `s` 解释掉，`s_min_full(v)` 会近乎平坦，曲面在部署期将退化为一个 s 阈值。
- **方法**：秩残差化后的 partial Spearman；以及在每个 s 十分位**内部**按 v 中位数劈半比较 `y10` 中位。
- **结论**：

  | 量 | 值 |
  |---|---|
  | Spearman(s, v) | −0.197（弱相关，不冗余） |
  | partial Spearman(y, v \| s) | **+0.259**（保住边际 +0.304 的 85%） |
  | s 层内 v 造成的中位差 | 9/10 档为正，均值 **+0.36** |
  | 参照：s 自身跨档动态范围 | **1.38** |

- **我的读法**：退化风险看起来排除了，但 `v` 的增量效应约为 `s` 的 26%——**margin 不宽裕**。
- **没排除（这条我特别不确定）**：以上全是 fit split 上的描述性统计，**`y` 到 SR 的映射根本没有建立**。偏差中位数低 0.36 会不会换成 `D_sr` p5 ≥ 0 且 `D_c` p95 ≤ −5%，这些数字答不了。

### 2.8 ~~头条数字自查：`tt/wt` 的比值可能超出理论上界~~ 【推导前提不成立，见 §7.2】

这一条是我**自己回头查出来的问题**，不是审查提出的。之所以放进检验一节，是因为它直接影响 §2.4 的结论强度。

- **方法**（纯推导，无新实验）：设 teacher 采样 `X ~ (μ, σ²I)`，维度 d。则 `E‖X₁−X₂‖² = 2σ²d`；而对**任何确定性输出 c**，`E‖c−X‖² ≥ σ²d`，等号在 `c = μ`（条件均值，c 的最优取值）处取到。高维下范数集中，于是

  **`tt / wt ≤ √2 ≈ 1.414`**，且这个上界对"缓存输出是最优点预测"的理想情形也成立。

- **观察**：实测 `ratio_median = 1.956` **超出该上界**。
- **已排除的解释**：不是抽样步不同步——`per_step.jsonl` 每行同时带 `tt_median` 与 `wt`，取自同一步。
- **尚未验证的可能解释**：
  1. **teacher 分布多模态**。中位数聚合下，跨模态的 `tt` pair 会抬高 `tt` 中位，而 `wt` 可能稳定落在主模态内；多模态／重尾容易破坏 √2 关系。
  2. 度量是「h_exec 步上加权 L2 的**均值**」，是范数的均值而非范数本身，上述逐步近似未必严格适用。
  3. `tt`/`wt` 的实现存在我尚未看出的不对称。
- **已查的部分（2026-08-28，只读现有产物，不占 GPU、未动任何判据）**：

  我先怀疑异常来自**聚合口径**——脚本的 `ratio_median` 是 `median(tt_pooled) / median(wt)`（1400 个 pair 对 50 个值），是混合池的中位数之比，而 √2 上界是逐观测命题。于是用 `per_step.jsonl` 重算配对口径：

  | 口径 | 值 |
  |---|---|
  | 脚本报的 ratio-of-pooled-medians | 1.956 |
  | 用 per-step `tt_median` 重算的 ratio-of-medians | 1.994 |
  | **配对口径 `median(per-step ratio)`** | **1.797** |
  | per-step ratio 的 p5/p25/p50/p75/p95 | 1.05 / 1.45 / 1.80 / 2.26 / 2.83 |
  | **单步超过 √2 的比例** | **38/50 = 76%** |
  | 单步超过 2 的比例 | 18/50 |

  **结论：聚合口径不是成因，该解释被排除**——配对口径仍为 1.797，且 76% 的单步各自超标，异常在逐观测层面就存在。

  **新增旁证**：跨 50 步 `Spearman(tt_median, wt) = +0.045`，**两者几乎不相关**。若二者由同一处局部「难度／离散度」驱动，本应正相关；不相关支持「它们在测不同的东西」，与上面对 `tt`/`wt` 对象不同的更正一致，也与多模态解释相容（`tt` 的 28 个 pair 含跨模态对而被抬高，warm 补全则可能锁定主模态）。

- **仍未查的部分**：解释 1（多模态）需要 pair 级距离的分布形状，而 `per_step.jsonl` 只存了每步的 `tt_median`、没存 28 个 pair 本身——**要验证得改脚本重跑，需占 GPU**，故未执行。解释 2（度量是范数均值而非范数）未检验。
- **影响面（我认为必须先说清楚再让人引用）**：
  - **受影响**：「缓存误差约为 teacher 自噪声的一半」这个**定量**表述。若上界成立且解释 1 不成立，该说法应收回或改写。
  - **不受影响**：`tt ≫ wt` 的**定性**结论，以及 `tt` 中位（6.222）跨过 δ 网格上界（6.187）这一点——两者都不依赖 ratio 的具体数值。
  - 因此 §2.4 用来解释止损的那条链条本身不塌，塌的是我报给 owner 的那个头条句子。**在核实前我已在 plan §11 对该数字加了"不要引用"的警示。**

### 3.1 我认为的机制：offset 是 episode-max，随 episode 长度增长；δ 网格跨度不随之增长

| | spatial | l10 |
|---|---|---|
| fit split 每 episode 步数 min/**中位**/max | 15 / **22** / 44 | 35 / **50** / 104 |
| offset | 5.373 | 8.405（**1.56×**） |
| δ 网格跨度 | 2.554 | 2.501（**≈ 不变**） |

`oof_offset` 定义为「每 episode 内 `max(y7−q̂7, y10−q̂10)`」再取 50 个 episode 的第 49 位——
**它对 episode 内的步数取最大值**，episode 越长、抽到极端残差的机会越多，offset 就越大。
而 δ 网格是 `y10` 的**逐步分位跨度**，与 episode 长度无关（实测 2.554 vs 2.501，几乎相同）。

**若该机制成立，推论是：这个判据随任务时程变长而单调变难，且变难与方法质量无关。**
libero_10 是长程套件（中位 50 步，spatial 的 2.3 倍），于是尽管 (s,v) 信号明显更强，反而更过不去。
**我认为这个方向是反的**——通常不希望判据因为任务更长就惩罚它。

**我对这条的把握**：机制本身（episode-max 随步数增长）是定义层面的，我认为确定；
但「1.56× 的 offset 增长有多少归因于步数、多少归因于 l10 本身残差更重尾」我**没有分离**，
只有两个 suite 各一个点，n=2 不足以定量归因。这条应当读作**一个有定义支持的假说**，不是已验证的结论。

   `z_j`；先前“teacher 自噪声支配 coupled Y”的因果链无效。数学定稿
   `dispatch_note.tex` 的 *Random loss under coupled noise* 也已明确要求这一点。
2. **不接受更正后的两处过度表述**：共用 `z_j` 不等于“同一条噪声轨迹”；`Y` 也不能直接称为
   “真实的观测失配偏差”。它是**同一初始噪声下的配对反事实偏差**，其中 `Y_7` 还包含一次
   winner→current conditioning 的中途切换效应。
3. **目前没有证据表明 `run_stage3_from` 写错**。时间点、步数和 `num_steps` 契约在代码上相容；
   但现有测试只钉住步数，没有在真实模型／真实 payload 上钉住数值重放，因此实现嫌疑尚未被最终排除。
4. `y7 > y10` 的极端集中现象属实，但“offset 完全由那条失败 episode 尾巴决定”**不属实**。
   真正决定数值 offset 的是第二大的 episode-max OOF residual；l10 中它来自另一个**成功** episode。
5. “episode 越长 ⇒ 本判据必然单调更难，且与方法质量无关”只能作为待验证假说，不能作为
   定义层面的已证机制。它只在**固定模型、固定既有残差序列、仅追加新步**时成立；跨 suite 会重拟合
   edges、曲面和 OOF residual，offset 当然也依赖方法质量与残差分布。

### 7.2 fresh 的精确语义

代码实际对应：

\[
a_{10}=F_{c_j}^{1\to0}(z_j),\qquad
a_{0}=F_{c}^{1\to0}(z_j),\qquad
a_{7}=F_c^{0.3\to0}\!\left(F_{c_j}^{1\to0.3}(z_j)\right).
\]

因此：

- `Y10 = D(a10, a0)` 比较 winner conditioning 与 current conditioning 下、共用 `z_j` 的两次完整流；
- `Y7 = D(a7, a0)` 比较“winner conditioning 跑前 7 步、current conditioning 跑后 3 步”的混合流，
  与“current conditioning 跑满 10 步”的完整流；
- 两支只有初始随机数相同。由于 conditioning 不同，它们从第一步起就会分叉，到了 `t=0.3` 时
  `x_{j,0.3}` 与 current-reference 的 `x_{c,0.3}` 通常已经不同；所以“同一条噪声轨迹”是错误措辞；
- common-random-number coupling 消除了**独立重抽噪声造成的比较地板**，但 `Y(z_j)` 仍会随 `z_j`
  变化，也可能存在 `z_j × conditioning` 的交互重尾。故“没有独立噪声方差”可以说，
  “Y 中完全没有噪声影响”不可以说；
- `Y10` 是配对 counterfactual，不是实际闭环误差；`Y7` 更不是“纯观测失配”，因为它还测量混合
  轨迹的路径依赖。建议统一称为 **coupled conditioning/path mismatch**。

这也意味着 §2.8 的 `√2` “异常”无需再查多模态：该推导要求 `c` 是与 teacher sample 独立的确定点，
并约束的是期望平方距离／RMS；这里 warm 输出 `C(z_j)` 与 reference `X(z_j)` 共用同一个 `z_j`，
脚本报告的又是加权 L2 均值的中位数。三项前提都不成立。`tt/wt > √2` 在当前口径下不构成异常，
也不能支持或反驳 coupled Y 的质量。**不建议为此再占 GPU 跑 §6.1 的多模态检验。**

### 7.3 `run_stage3_from` 的实现审计

静态链路一致：

- rebuild 以 `NUM_STEPS=10` 生成 action 和 intermediates，并把
  `payload.denoising_num_steps=10`；
- `_stage3_with_intermediates` 在 step 7 的 denoise **之前**保存 `t=0.3` 的 `x_t`；
- `run_stage3_from(start_t=0.3, num_steps=10)` 用同一个 `dt=-0.1` 执行 3 步；
- `_warm_start_num_steps` 的回归套件为 **16 passed**；另用非线性确定性 fake denoiser 做同 conditioning
  的 full-vs-resume 检查，最大绝对误差为 `2.98e-8`（浮点时间累积量级）。

所以 `num_steps=winner_payload.denoising_num_steps` 本身不是可见 bug，反而是恢复原时间网格所必需。
同时，这个检查不能替代真实 payload 审计：sidecar id 错配、pickle 中间态损坏、真实模型路径不等价等问题
仍需用下述 D0 检查排除。

`y7 > y10` 也不违反一般数学定理。对非线性 flow，把一个在错误 conditioning 下走到 `t=0.3` 的状态
切换到 current vector field，并不保证它到 current reference 的距离收缩；晚期修正完全可能把它推得比
winner 的最终 action 更远。因此它是重要的经验性 (A1) 违反／失败模式，但**单凭不符合设计愿望不能判为代码 bug**。

### 7.4 用真正 OOF residual 复算尾部归因

输入 fresh 表 SHA256：spatial `5fe2daa5…c015be`，l10 `dde9cfe7…6bad1`。我没有用 raw `y7`
代替 offset，而是重新执行当前 `assign_folds → fit_fold_models → oof_predictions`，按代码计算
`max(y7-q7, y10-q10)` 的 episode max。

| suite | 最大 episode score | 第二大 episode score（实际 offset） | 数值 offset 的来源 |
|---|---:|---:|---|
| spatial | 11.1904，失败 ep `0121` step 37，`y7=18.3371` | **5.3733** | 成功 ep `0130` step 15，`y7=10.7147` |
| l10 | 11.4144，失败 ep `0042` step 99，`y7=19.7737` | **8.4047** | 成功 ep `0057` step 43，`y7=15.4696` |

原文的 raw-tail 统计可复现：spatial 的 `y7>p99` 为 12 行、其中 10 行 `y7>y10`；l10 为 30 行、
其中 22 行 `y7>y10`；全体比例分别为 49/1134 与 154/2985。错误发生在把这组 raw-y7 画像直接称为
“决定 offset 的行”。offset 用的是 **OOF residual 的 episode 级第二大值**，不是 raw y7 的 top-5。

l10 的失败尾部仍然重要：它提供最大的 episode score，使另一个 episode 成为第 49/50 序统计量；
但它既不是 offset 的数值来源，也不是唯一支撑点。即使只讨论当前固定 OOF 预测，这也是至少两个 episode
共同造成的尾部现象。不能把根因收缩成“单条失败尾巴”。

### 7.5 对 episode-length 解释的裁决

episode max 的确有长度效应：对同一 episode、固定 `q`、保留原步骤再追加步骤，max 不会下降；固定 50 个
episode 时，其第 49 序统计量也不会下降。但本次 spatial→l10 比较同时改变了任务、状态分布、每折 edges、
拟合曲面和 residual 分布，因此 `5.373→8.405` 不能由 `22→50` 步单独解释，也不能说“与方法质量无关”。

还有一个目标语义问题：如果证书本来要保证“一条 episode 的所有 step 与所有正深度同时安全”，
随 episode 变长而更保守是该目标的自然代价，不自动构成判据缺陷。真正值得重审的是：
**δ 候选来自逐步 `y10` 分位跨度，而 δ 选择又把一个 50-episode、第二大 episode-max OOF residual
整体平移到每个格点，随后 calibration 还会再做一次正式 episode-max conformal correction。**
这可能是选择期与认证期的双重保守／口径不匹配；当前两 suite 的结果证明它在本数据上决定性地压空接受域，
但尚不能仅凭 n=2 宣称一个普适的长度定律。

### 7.6 放行前的最小 D0 检查与后续裁决

在修改预注册规则或消耗 A′ 前，只做离线 logged-state 检查：

1. **真实模型 self-resume parity**：对普通行和上述四个极端 episode，用 current conditioning + `z_j`
   生成带 `x_{c,0.3}` 的 full reference，再从该 `x_{c,0.3}` 用同一 current stage2 resume；两者应在预设
   数值容差内一致。失败即实现 bug，当前表全部作废。
2. **payload/sidecar 身份闭环**：对 winner 用其原 conditioning + sidecar `z_j` 重放，逐项比对 pickle 中
   `x_{j,0.3}` 与 action；同时断言 `denoising_num_steps==10`。失败即重建／join bug。
3. **极端行路径分解**：记录 `||x_{j,0.3}-x_{c,0.3}||`，并比较 direct winner、hybrid warm、current full；
   再从普通 matched controls 取同样统计。若 1/2 通过而极端行仍稳定 `y7>y10`，应把它裁定为真实的
   hybrid-flow 失败模式，而非继续猜实现。

这些检查只重放 fit 表中的 logged observations，不是 rollout，不触碰 A′，也不改变任何判据。

若 D0 全过，我建议把本次冻结协议如实记为**负结果**，但另开一个明确标注 post-hoc 的 revised protocol：
在 fit split 内用 cross-fitted deployed verdict 选择效用 operating point，**不要再把一个 episode-max 95%
offset 当作全曲面的统一 boundary shift**；δ 冻结后，只让未查看的 calibration split 做一次正式 simultaneous
conformal correction。这样把“选哪个点”和“最终证书”分开，避免选择期和认证期重复支付同一类极端值税。
是否采用该新版规则必须先形成新预注册记录；不能覆写本次止损，也不能拿同一结果冒充原协议成功。
