# R16 registration adapter

D1–D6 in `COORDINATOR_DECISIONS.md` govern this implementation. `PROTOCOL.md` is a byte-for-byte copy of R14's frozen protocol. This adapter records the required layout and cost changes, following R15's five-arm adapter; it does not revise the parent registration.

- 32 cells: sizes 50/100/200/500 × models π0.5/GR00T × suites L10/Spatial × k=1/2. Every server is local; every worker is timan107. Roots carry `intended_host=local`, with no fleet binding. Runtime analysis additionally checks the launch receipt.
- Size 50 copies R14's exact B manifests. Other sizes copy R15 D2's exact manifests. Existing full-step dev C10 references are reused, with pair/seed/template, original bytes and fit hashes bound in `design.json` and `reference_reuse.json`. R15's previously proven library-independent C10 behavior applies unchanged. No replacement full-step reference is needed.
- Only `miss.num_steps` and matching GR00T live-head K change in each inherited dev/phase-1 arm. All client flags, seeds, fits, libraries, caps, guards and correctors remain unchanged. `replan_steps=5` plus one policy tail still commits controls 0–9 of each policy chunk. Size 500 retains the existing LOEO wrapper and its `r15d_` B UID prefix; fits still include the query episode.
- The full-step C10 construction-pass sentinel is distinct from the executed k-step C10 fallback. Lower levels always compare against full-step C10. If ir45 fails, fallback is k-step pure inference without another qualification test. Its measured SR may itself fail the full-reference tolerance; disclose this. Sixteen shared k-C10 B arms (two init designs × two models × two suites × two k values) are necessary for the parent protocol's stitched fallback SR/IR estimates. They do not affect descent selection.
- Visit ir45 → ir40 → ir32 → ir25 → off and stop on the first failure. Keep 0/2/5 pp tables; 5 pp is primary. Equality passes. Uniform uses all 300 paired episodes. Retain gains/losses, conservative CP paired intervals, first-failure recovery diagnostics, confidence sensitivity and 5,000 within-task paired bootstrap draws, seed 20261005. Family=200 separately within each four-cell size × k group, following R15; no cross-group simultaneous claim. Allocation arms/diagnostics are not repeated, following R15's adapter.
- D5 vision coefficients stay .152/.148. Reduced-call coefficients are computed at full precision from `analytic_cost.py` and `cost_groot_libero_measured.json`. Full references retain .848/.852. Preserve and reconcile the original stage ledger separately; its rounded π0.5 shares are not the D5 price authority.
- Phase 1 uses the original R14 A templates and pure C10 fits, with 500 exact identities per arm. Test A emission needs all 32 primary task/uniform tables and an immutable `TABLE_FREEZE.json`, and verifies registered source hashes before writing any roots. It emits one mixed-task arm per cell (32 arms), with no refit and no test-driven selection. `queue_test.txt` stays empty until that emission.
- Test A measures each cell against R14 full-step pure C10 and the same-size full-step task descent (R14 at 50, R15 otherwise). Pool first within each size × k (2,000 outcomes, 1,000 original suite/task/init clusters); also report descriptive per-k equal-size mixtures. The latter repeat references as weights, not new independent trials; their intervals use the same paired cluster draws shared across sizes, models and k. No between-run uncertainty or independent validation claim is made.
- Loader discipline matches R14/R15: last accepted terminal error-free journal record per UID, last accepted attempt's uid/step decision in sorted shard/line order, exact balanced identities, contiguous steps, source/served fit verification, LOEO donor audits, counts and stage ledger reconciliation. Snapshot/hash every read input and reject changes before writing. Existing deterministic H100 relocation verification is retained for historical π0.5 references.
- One unavoidable shared edit permits the explicitly requested `groot_n15_k1_v1` schedule, with no recoverable warm-start points. Existing schedules are unchanged. Original bytes and the atomic edit's diff are archived here. The CPU proof uses deterministic forward stubs; real-weight and environment checks are left to the coordinator's isolated two-episode smoke roots.

`DESIGN_LOCK.json` seals the pre-outcome design and implementation; it refuses subsequent source drift. Future source fixes need an explicit, reviewed new registration rather than silent edits to frozen outputs.
