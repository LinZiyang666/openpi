# R16 conductor handback

Built four resident dev groups under `r16_conductor_dev_{pi05,groot}_k{1,2}_v1`, two isolated smoke groups, `queue_conductor_dev.txt`, `queue_conductor_smoke.txt`, an episode scheduler/strategy over the existing conductor, and a resumable tmux runner. Each group contains 44 original methods. π0.5 uses three local servers; GR00T uses four, two per suite checkpoint. Workers use the existing LIBERO runner and pull from one group queue. Nothing was launched or synced; the running coordinator and its roots/queue/logs were untouched.

The primary 30-episode, 5 pp first-failure rule is unchanged. Lower levels stop after a task fails; k-C10 fallback is scheduled where needed. Fourteen completed B arms were imported with hashes, including all eight size-50 C10 arms. `refresh-reuse` captures further completions before unused groups start. Uniform tables are dropped. `analyze dev --conductor` handles partial cohorts and `analyze freeze` seals them; the frozen emitter later creates all 32 × 500 test-A arms and four nonadaptive resident test groups. No A outcomes were read and nothing was refitted.

Original `DESIGN_LOCK.json`, `design.json`, `PROTOCOL.md`, `protocol.json` and D1–D7 remain intact. `CONDUCTOR_AMENDMENT.json` and `CONDUCTOR_LOCK.json` register the layout amendment and narrow collector-format/path validation fixes. Numerical selection, pricing, pairing and test estimators remain unchanged. All new serving behavior is confined to explicit R16 entry points; no shared runtime source was edited.

CPU proof: all 176 dev methods, 4,224 decisions, two interleaved connections each; saved action bytes and decision semantics match standalone execution. It covers 656 guard MISSes, 494 periodic MISSes, 1,296 blind tails and 192 pure policy calls (`conductor_runtime_proof.json`). The expert forwards are synthetic; lower layers and frozen methods are real, with recorded B observations. Original default-step replay remains sealed. All 184 synthetic/regression tests pass (`conductor_tests.xml`); they cover cohort gating, first-failure equivalence, cross-endpoint dispatch, error exclusion, resume/stale-result fencing and mocked coordinator lifecycle/agent leases.

Fits add 0 GPU bytes. Unique CPU array footprints: π0.5 412.204 MiB for 44 methods; GR00T at most 361.568 MiB per process (the complete two-suite set, while actual processes hold one suite). Owner measurements imply ~27 GB steady for three π0.5 servers and ~24 GB for four GR00T servers. Coincident π0.5 peaks could reach 29.7 GB, so the 28 GB peak limit still needs the coordinator smoke. Starts are sequential and free memory is checked.

If tasks visit an average of two or three levels, episode work falls by about 1.7–2.5×; saved restart/tail time could bring total speedup to roughly 2–3×. This is an estimate, not measured. The full ladder has 48,000 descent episodes plus 4,800 fallback episodes (4,200 already reused here). Adaptive descent runs `9,600 × mean levels visited` plus only needed unmeasured fallback cohorts. There are four model/k lifetimes instead of 176 arm lifetimes. If every level passes, compute savings are smaller; GR00T retains its checkpoint-specific suite tail and every group retains a final tail.

Commands and checks: see `RUNBOOK_CONDUCTOR.md`. Build/sync the isolated `conductor_deployment/worker.tar`, then `bash exp/offline_search/rounds/r16/conductor_commands.sh smoke`. After smoke, start the same script with `dev` in tmux. Re-run after interruption; accepted episodes stay completed, in-flight attempts are fenced and reissued. The runner respects existing orchestration/fleet leases and uses the existing tether transport. A hard controller loss expires its detached agent within 90 seconds. Dev analysis/freezing and test emission/run commands are in the runbook.

Open risks: real model/simulator/network smoke was not run; π0.5 peak quota is unproven. One completed π0.5 size-50 k2 fallback has 40 overwritten server-log episodes; hash-audited accepted client receipts recover exact pure-C10 SR/cost counts, but their historical `miss_k` cannot be independently checked. This limitation is preserved, with no fabricated decision rows. Frozen source/input hashes must remain stable after table selection.
