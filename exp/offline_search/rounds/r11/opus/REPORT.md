# R11 第四层（推理开销旋钮）：按时间表调用大模型 —— opus 探索报告

2026-10-02 21:15 CDT。离线分析，只用示范库，没有跑任何闭环。（opus 子代理写此文件被拦，由协调者按其交回原文代存。）

## 给 owner 的结论（白话）

**这轮做了什么**
- 研究了两种"按时间表"调用大模型的旋钮：
  - **随机调用**：每个决策点以固定概率调一次大模型；
  - **定期调用**：离上次调用大模型隔几个决策点就调一次。
- 建了一本离线"开销账"：给定旋钮设置，只用示范库就能算出在现有三层设计上会花多少推理开销。账本和代码已放在本目录，astra 可以直接用来核对她那一侧按状态触发的方法。

**一、旋钮和开销的对应关系，离线就能算准**
- **公式**：
  - 现有三层设计里，大约一半的决策点要看图；
  - 每个看图点要么用缓存（便宜），要么调大模型（贵）；
  - 开销 ≈ 看图点比例 ×（缓存价 + 大模型价 × 调用比例）；
  - 调用比例 = 守卫自己调用的比例，加上旋钮在其余点上新增的调用。
- **用旧数据检验**：R6 有 13 个"守卫 + 随机加调"的配置。只看已公开的汇总数，这个公式预测的开销与实测相差 −0.003 到 +0.011。前提是知道闭环里守卫自己调用的频率。
- **唯一离线看不到的量**：闭环里守卫调用的频率。
  - 示范库重放给出的估计，大多比闭环实际偏高 0 到 0.045。这是对照 R10 已公开汇总数得出的，只用来检验，没有拿来调任何参数。
  - 其中约 0.01 来自"留出一集后库变小"，这部分可以只用示范库校正。
  - 换算到开销，误差在 ±0.02 以内；目标开销越高，误差越小。
- **预计实际开销**：每个配置都落在目标 ±0.02 以内。π0.5 会略低于目标，GR00T 长任务 50 集库会略高。

**二、定期调用和随机调用：离线差别只在"缓存连续开多久"**
- **打中缓存误差的能力一样**：离线比较两种方式调大模型的位置上"缓存与大模型动作的差距"，差别在 ±8% 以内，可以看作一样。
- **缓存连续时长不一样**：开销 0.25 时，
  - 随机调用平均每集最长连续用缓存 6 个看图点，长的一成达到 10 个点（约 100 步控制）；
  - 定期调用最多 3 个点；
  - 开销 0.32 时，定期调用基本是"缓存一次、大模型一次"交替。
- **这个差别有没有用，只能闭环测**：离线重放走的是大模型自己的轨迹，看不到缓存误差越积越大。
- **R6 的旧迹象**：定期调用比随机多 1 到 3 个点，三处方向一致，都不显著，而且底座不同。
- **我的预测**：定期比随机合并后平均多 0.6 个点。单个组合看不出差别，要把 16 对合在一起看。

**三、不建议做的**
- **开局先调大模型**：开头几步缓存反而最准，误差只有平均的 0.7 到 0.95 倍，花在这里浪费。
- **守卫调用后冷却一段时间**：守卫刚调用后的几个点，缓存误差反而更大（平均的 1.0 到 1.3 倍），冷却会躲开最该调的地方。
- **在已接近纯推理的大库上加开销**：长任务 200/500 集库的三层设计已经和纯推理只差 1.4 个点以内，预计加开销没用。只各放一个检查点，用来回答"该不该花"。

## 技术部分

**方法（SPEC.md）**
- **随机调用**：守卫没有触发的看图点，用按"任务、起始状态、步数"哈希出的均匀数，以概率 ρ 调用大模型（R6 ExtraDose 的同一做法，换了键）。
- **定期调用**：守卫感知的抖动间隔上限。K 是两次调用之间允许的平均缓存看图点数，任何来源的调用（守卫或旋钮）都会把计数清零。K 的小数部分在每个间隔上用哈希抖动实现，状态全部由已执行历史推出。
- **两个变体**：
  - 定期调用 + 守卫调用后再调一个点；
  - 随机调用一次连调两段。
- **共同约定**：所有调用都和守卫调用一样执行（一段大模型动作块 + 一段提交的大模型尾巴，然后重新检索），不改守卫状态，修正器照常工作。

**开销账本（IR_MODEL.md，`ir_model.py`）**
- **账本公式**：IR = v(c_v + c_m f)，f = g + (1 − g)k，即守卫优先，旋钮只作用于其余看图点。
- **守卫调用率 g 的来源**：在示范库上按 5 折整集留出重放部署时的检索，并逐行移植冻结的"无进展"判据。移植经自检与冻结函数完全一致；逐行误差与 R10 opus 的 k 折输出完全一致（最大差 0）。
- **用 R6 汇总数核对重叠规则**：13 个配置上，预测减实测为 −.003 到 +.011。
- **离线看不到的部分**：闭环守卫调用率、闭环集长权重、旋钮对守卫的反馈、额外看图。各项的界和压力测试见 IR_MODEL §5：守卫调用率在 ×.75 到 ×1.25 之间变动时，开销移动 ±.004 到 ±.027。

**离线曲线与价值证据（OFFLINE.md）**
- 8 个组合 × 各方法的"旋钮 → 调用比例 → 开销"曲线，各档目标的求解，以及压力测试。
- **风险代理**：大模型动作与修正后缓存动作的留出误差，由 R10 opus 的 k 折头部项精确重构。
- **捕获率**：随机 1.00，定期 .92–1.02，"守卫后再调一次" 1.01–1.06，开局先调 .89–.97，冷却 .90–.98。
- **结构差异**：定期调用把最长连续缓存段从随机的 3.7–6.4 个点压到 1–3 个点；高误差连续段（≥ 3 个点）减半甚至清零。
- **这项证据的分量**：
  - 对成功率分量低。R6 里按预测分歧放置调用、捕获量远高于此，结果仍与均匀放置持平。
  - 对开销分量高。
