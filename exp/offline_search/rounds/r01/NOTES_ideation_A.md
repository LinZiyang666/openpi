## 1. Proposals (≤4), in the brief's format

### P1 `tail_continuity` — select the library chunk that *continues the plan the robot is already executing*; no vision, no modalities, no weights
1. **Pitch**: in the fresh regime (previous decision was a policy call) the policy's own unexecuted tail `prev_a_exec[5:10]` is the query; the library is indexed by action heads (35-d). Selection happens in action space.
2. **Hypothesis**: the current frame asks "which stored *observation* looks like mine" through saturated 32768-d cosines whose rank correlation with action error is .1–.5. But replan-5 throws away half of every chunk, and that half is the teacher's own prediction of the next 5 steps (err .21–.28 to the fresh teacher sample, ≈ the noise floor ×1.6). Matching library heads to it converts a hard perception problem into a 35-d nearest-neighbour problem with a monotone, well-calibrated distance. It also fixes the "stay" pathology (the tail moves forward by construction) and lowers gripper mismatch (tail carries the planned flip).
3. **Algorithm** (Method API):
   - `fit(lib, ctx)`: `B = ctx.open_library("bpool_all")` for GR00T; for π0.5 `B = ctx.open_library("bpool_cs")` (April `bpool_all` ≈ current) and `ctx.register_library("bpool_cs_reg", action=B.action, progress=B.progress, task_id=B.task_id)`; return `Result(library=<that name>)`. Per task t: `H_t = (B.action[rows_t, :5, :7] / ctx.action_sigma).reshape(C,35)` float32 contiguous; keep `rows_t`. Hash set `S = {bytes(np.ascontiguousarray(a[:, :7])) for a in lib.action} ∪ same over B.action` (dims :7 only — GR00T dims 7..31 are noise). Also build P2's structures for the fallback.
   - `reset`: nothing (no cross-decision state needed).
   - `query(q)`: `fresh = q.step ≥ 1 and bytes(np.ascontiguousarray(q.prev_a_exec[:, :7])) ∉ S`. If fresh: `T = (q.prev_a_exec[5:10, :7]/σ).ravel()`; `d = sqrt(mean((H_t − T)², axis=1))` (RMS over 35); `o = argsort(d)[:5]`; weights `w_i = exp(−(d_i/d_0)²)`, normalized; `action = Σ w_i · B.action[rows_t[o_i]]` (full (H,32) chunk); `topk = rows_t[o]`, `scores = −d[o]`, `confidence = −d_0` (default). Else → P2's rule (step 0 and stale regime). Only `[5:10]` of the tail is used for both models (GR00T two-segment `[5:10]`+`[10:15]` measured *worse*: .363 vs .344).
   - Fitted parameters: none (T0); σ from ctx. Optional T1 calibration for the confidence variant: τ_c = median over library rows r with prev ≥ 0 of `‖head(r) − tail(prev(r))‖_σ`, τ_a = median top-5 dispersion on library rows; `confidence = −d_0/τ_c − disp/τ_a`.
4. **Predicted effect**: inf cells err .25–.28 (B0 .47–.54; also below the current-library oracle in 3/4 inf cells), p50 .19–.21, AURC .19–.22 (B0 .37–.43), risk@30 .17–.20 (B0 .34–.39), grip mismatch .02–.07 (B0 .04–.09); `indist` on π0.5 should rise several-fold (p50 .21 vs floor median .12–.14; B0's 4–6 % is with p50 .39–.42). Cache cells: identical to P2 (its stale branch). Cost: 140 B/entry for the head index (+ P2's 96 B), ~0.05 ms/query, fit seconds.
5. **Tier**: T0. Deployment: the online system already has the executed chunk; the only new input is its own HIT/MISS flag (see §4). Closed-loop implication to verify later: every decision right after a MISS can be served at ≈ teacher-noise quality with a reliable confidence, so a ≥ 50 % hit rate at near-teacher quality is structurally available regardless of vision.
6. **Kill criterion**: inf-cell err not ≤ 0.35 in every inf cell, or AURC not ≤ 0.28 (i.e. the harness disagrees with my measurements by > .05), or the analysis agent shows the gain is confined to early steps (my per-third check: early/mid/late cont3 = .28/.39/.36 vs B0 .41/.56/.52 on π0.5-sp-inf, so it should not be).
7. **Cheapest diagnostic first**: already done (diag1/3/5/6). For the implementation: `harness.smoke` on `pi05_spatial_inf` must show err ≈ .26 and flip rate ≈ .8 vs B0; `profile.breakdown --slices third,grip` and `timeline` (expect switch-heavy, run length ≈ oracle's 1.6–2).
8. **Variants**: k ∈ {1, 3, 5} and plain vs kernel mean (measured on 10× lib: k1 .291/.302/.281/.290, k3 .269/.287/.257/.273, k5 kernel .263/.283/.249/.267 inf); library current vs 10× (current k3 .345/.330/.344/.336); confidence −d₀ vs −d₀/τ_c − disp/τ_a (measured z-sum: .183 .216 .178 .208 vs .193 .217 .191 .205 inf). Reference row worth adding as *reference only* (violates the library-action rule): `tail_passthrough` = execute the tail itself, err .248/.284/.207/.240 — the ceiling of the fresh regime and a policy question for the owner (it is replan-10 semantics for one decision, not a policy call).

### P2 `state_window_bigpool` — the observation side without vision: 3-step robot-state window on a 10× library, mean of top-5
1. **Pitch**: represent "where am I" by the last three 8-d robot states (24-d, z-scaled), retrieve from all 500 build episodes per suite, return the mean of the 5 nearest chunks.
2. **Hypothesis**: B0's vision keys cost 262 KB/entry, which forced a 50-episode library; coverage (10× library → oracle −40 %) matters more than key quality, and robot state is the field with the highest sim↔err rank correlation already (.27–.53) and is immune to the April/Sep render drift. A short window adds phase/velocity without score smoothing. Consensus de-noises the stochastic teacher (err is against one sample; the conditional mean is closer than any single sample) and averages near-equivalent candidates.
3. **Algorithm**: `fit`: open the 10× library as in P1; `sd = std over valid dims of B.rs` (use `dims.valid_state`); library windows `W = [z(rs_r), z(rs_prev(r)), z(rs_prev²(r))]` with `prev` pointers, padding by repeating the oldest available row; per task contiguous float32 [C,24]. `query`: `x = [z(q.rs[:8]), z(q.hist_rs[-1][:8]), z(q.hist_rs[-2][:8])]` (repeat the oldest when history is shorter; step 0 → three copies of `q.rs`); Euclidean `d`; `o = argsort(d)[:5]`; `action = mean of the 5 full chunks`; `topk = rows_t[o]`, `scores = −d[o]`, `confidence = −d_0` (variant: `−d_0/τ_w − disp/τ_a`, τ_w = median library 1-NN window distance within task, τ_a as in P1). Fitted parameters: `sd`, τ's — library only (T1, ms).
4. **Predicted effect**: standalone on all decisions: err .37 .60 .34 .54 .38 .45 .37 .51, AURC .29 .38 .28 .37 .31 .34 .31 .38 (see 0e); as P1's stale/step-0 branch it produces the cache-cell rows of the table in 0g (err −.04 to −.17, AURC −.02 to −.07, grip mismatch on transitions −.02 to −.17). Cost 96 B/entry, ≈ 0.03 ms/query on 2,800 candidates.
5. **Tier**: T0/T1. Deployment: the library can be every rollout ever collected (and grow online) at ~100 B per decision; no image encoder in the retrieval path.
6. **Kill criterion**: on the 10× library it does not beat B0-current on err in ≥ 7/8 cells, or `B0 + consensus on the 10× library` (vision, same library size, see §4 ablation) beats it by ≥ .03 err in the cache cells — then vision earns its cost and P2 becomes the cheap fallback only.
7. **Cheapest diagnostic first**: `profile.repr --encode <file>:state_window --metric l2 --lib bpool_all` (expect rho and orc_rank better than `rs` alone); already measured end-to-end (diag5/6).
8. **Variants**: m ∈ {1, 3}; k ∈ {3, 5, 8}; library current vs 10×; success-only filtering of the 10× library (measured for continuity: no effect, .270 vs .269); adding velocity `rs_t − rs_{t−1}` explicitly (already implicit in the window).

### P3 `topk_action_consensus` — a universal selection/confidence rule: never return top-1, return the mean of the top-k and use their agreement
1. **Pitch**: for *any* ranking (B0, B1, agent B's methods, P1, P2) replace top-1 by the σ-normalised mean of the top-k chunks; confidence = ranking score of top-1 plus the negative dispersion of the k chunks.
2. **Hypothesis**: the target is one stochastic teacher sample (π0.5 floor p50 .12) and candidate sets contain several near-equivalent chunks with different noise; the argmin of a noisy score is a high-variance estimator, the mean of the top-k is a lower-variance one. Dispersion of the top-k is an ensemble-disagreement signal the fused score lacks (it flags multimodal / transition states). The oracle's frequent switching (45–60 %) between near-ties is the same phenomenon seen from the other side.
3. **Algorithm**: wrap `baselines.B0Current` (or any method exposing per-candidate scores): `o = argsort(−S)[:k]`, `action = mean(lib.action[o], axis=0)` (full chunk; gripper sign = sign of the mean; optional majority vote on dim 6), `topk = o`, `confidence = (S[o_0] − μ_S)/σ_S − disp/τ_a` with `disp = RMS over [5,7] of (a_i − mean)/σ`; μ_S, σ_S, τ_a from library-side statistics at fit (T1) or simply `confidence = S[o_0]` (T0).
4. **Predicted effect** (B0 ranking, current library): err −.05 to −.08 in all 8 cells (0f), p50 similar; AURC −.03 to −.08 in inf cells and −.01 to −.03 in cache cells with the combined confidence (dispersion alone is worse than the score in π0.5 cache cells: .470/.445 vs .420/.389); grip mismatch roughly unchanged; cost unchanged (same ranking). Composes with every other proposal.
5. **Tier**: T0 (T1 for the calibrated confidence). Zero deployment change beyond returning a mean chunk.
6. **Kill criterion**: any cell where the mean of top-5 is worse than top-1 by > .01 (I measured none), or closed-loop later shows averaged chunks are harmful (e.g. gripper hovering at 0 — mitigate by majority sign).
7. **Cheapest diagnostic first**: `profile.compare` of `B0_current` vs `B0_cons5` (paired, episode bootstrap) — expect win rate > .6 everywhere. `explain --worst` on cons5 to check multimodal cases (left/right ambiguity) where the mean is bad; if frequent, switch to medoid (measured medians are worse than means, so medoid is the only alternative worth trying).
8. **Variants**: k ∈ {3, 5, 8}; plain vs kernel-weighted by score gap; medoid; majority-vote gripper; confidence = score / dispersion / both.

### P4 `library_row_filter` — Bayesian (HMM) forward filter over library rows with `next`-transitions, replacing per-decision kNN
1. **Pitch**: keep a belief over library rows within the task; move it forward along library trajectories each decision; update with cheap emissions (state window, and continuity in the fresh regime); output the posterior-weighted consensus and a posterior-concentration confidence.
2. **Hypothesis**: kNN re-decides from scratch every 5 steps, which is why B0 "stays" 11–35 % of the time (highest err) and why cache-arm ranks collapse to p50 32–49 late in the episode. A transition prior along `next` accumulates evidence over the whole episode without smoothing scores (the settled negative), and the posterior entropy is a principled "am I lost" signal that the fused score is not (confidence barely drops on transitions). Evidence is indirect: tracking `next` of the previous pick alone already ties B0 in cache cells (.556 .572 .458 .626 vs .554 .575 .471 .645) and tracking-anchored consensus ties P3 (.528 .519 .423 .564); the exact previous row is identifiable (0c).
3. **Algorithm**: per task, rows `C` of the 10× library (or current). Transition `T(x'|x) = α[x'=next(x)] + β[x'=next²(x)] + γ[x'=x] + (1−α−β−γ)/C`, defaults α=.6, β=.15, γ=.1 (mass of missing `next` goes to the uniform term). Emission `e(x) = exp(−d_w(x)²/2τ_w²)` with `d_w` the m=1 state distance (the filter supplies history) and τ_w = median within-task 1-NN distance of library rows; in the fresh regime multiply by `exp(−d_cont(x)²/2τ_c²)`. Forward: `b ← e ⊙ (Tᵀ b)` (implemented as α·scatter-add along `next`, β along `next²`, γ·b, plus constant), normalise; `b_0 ∝ e_0`. Output: `o = top-5 rows of b`, `action = Σ b_i a_i / Σ b_i`, `topk = o`, `scores = b[o]`, `confidence = Σ_{i∈o} b_i` (variant: −entropy(b)). State = `b` (C floats), reset per episode — within-episode state only, deterministic. O(C) per query.
4. **Predicted effect**: fresh regime ≈ P1 (the continuity emission dominates); stale regime: the target is to beat P2 (.60 .54 .45 .51) by ≥ .02 and to lower AURC via entropy; probability maybe 40 %. Cost as P2 plus a C-vector per episode.
5. **Tier**: T0/T1 (τ's from the library; α/β/γ hand-set, sweep 2 settings).
6. **Kill criterion**: not better than P2 by ≥ .02 err in ≥ 3 of 4 cache cells, or AURC not better than P2's — then the transition prior is worthless offline and the idea is dropped (offline cannot show coherence benefits that only exist in closed loop).
7. **Cheapest diagnostic first**: a 200-line numpy script replicating P2 and adding the forward recursion on all cache cells (all arrays are tiny; ~1 min), before any harness implementation.
8. **Variants**: α ∈ {.5, .8}; emission m=1 vs m=3 window; library current vs 10×.

## 2. Ranking (gain × probability / cost)
1. **P1 tail_continuity** — largest measured effect (inf cells −45 % err, −50 % AURC; risk@30 halves), T0, trivially cheap, and it changes what the cache *is* (the fresh regime after every MISS becomes near-teacher-quality). Probability of holding in the harness ≈ 1 (measured on all decisions with the harness metric).
2. **P2 state_window_bigpool** — gains in all 8 cells including the drifted cache cells (−.04 to −.17), removes vision keys and unlocks the 10× library; probability ≈ 1; needed as P1's stale/step-0 branch anyway. Implement P1+P2 as one family with kwargs `fresh_rule ∈ {cont, window}`, `stale_rule ∈ {window, obs_cons}`, `lib ∈ {current, big}`.
3. **P3 topk_action_consensus** — smaller (−.05 to −.08) but universal, free, and composes with agent B's proposals; probability ≈ 1.
4. **P4 library_row_filter** — the only one without direct evidence; kept because it is the principled version of "history without score smoothing" and its diagnostic costs one minute.

## 3. Considered and rejected (measured)
- **Linear "predict the action, then select" embedding** (task-centred PCA-256 of v0|v1 + rs → ridge → 35-d action; nearest library action): err .74–.86 in every cell (worse than B0, near random). The tail-augmented version equals continuity alone (.373 vs .372). A T2 non-linear version is not worth it given P1/P2.
- **Whitened / task-centred joint Mahalanobis over vision keys** (256 whitened PCs, one L2, no per-modality weights): .485 .676 .485 .660 .561 .617 .566 .660 — worse than B0 in every cell. Saturation is not the binding constraint; the pooled vision keys simply carry little action-relevant information beyond the state.
- **Cascades / mixtures of observation ranking and continuity** (obs top-10 → continuity: .384 .638 .363 .607 .391 .597 .397 .634; continuity top-5 → obs: .412 .635 .366 .592 .426 .579 .390 .633; 85/15 z-sum ≈ continuity; gate on obs rank worse): never better than continuity alone in the fresh regime and ≈ B0 in the stale one. Cross-selector agreement as a confidence: AURC .27–.32 inf (worse than −d_cont .24–.25), .49–.56 cache (worse than B0).
- **Two-segment continuity for GR00T** (tail [5:10] and [10:15]): worse (.363 vs .344; .353 vs .336).
- **Gripper-context hard filter** (candidate's previous gripper command must equal the executed one): err +.005–.015, grip mismatch −.01 to −.02 on three cache cells, +.02 on GR00T-l10 — dropped; the gripper gains come for free from P1/P2 (transition-step mismatch .22–.55 vs B0 .32–.72). On π0.5 transitions everyone is already at the teacher floor (.18–.22); the remaining headroom is GR00T only.
- **Pure trajectory tracking as the selector** (always `next` of the previous pick): ties B0 (.556 .572 .458 .626 vs .554 .575 .471 .645 cache; slightly worse in inf); consensus dominates it. Survives only as P4's transition prior.

## 4. Notes for the coordinator
- **Regime flag legality**: the harness gives no HIT/MISS flag, but `bytes(prev_a_exec[:, :7]) ∈ library chunks` reproduces it exactly (100 % / 0 %). Online the system must pass its own flag (with consensus actions the executed chunk is no library chunk and the hash proxy would say "fresh"); note this in the method docstring and in `extras` (`x_fresh`).
- **Why the scoreboard will look regime-split**: inf cells = fresh regime, cache cells = stale regime (0b). Ask the analysis agent to report P1's numbers per regime and to treat cache cells as the stress test of the stale branch; closed loop alternates, so the realistic operating point is between the two rows.
- **Ablation worth one spare coding agent**: `B0 + consensus-5` on the 10× library (vision at equal library size; ~8–80 ms/query). If it does not beat P2 by ≥ .03 in the cache cells, vision keys can be dropped from the cache entirely (1,100× smaller entries, unbounded library growth).
- **Harness details**: `ctx.open_library("bpool_cs")` works (LibraryView takes any stored name) but `Result.library` only accepts `current`/`bpool_all`/registered names → register `bpool_cs` in `fit()`. `prev_a_exec` is the full (H,32) chunk (api.py:277). Big libraries have `prev`/`next`/`progress`, so `phase_err` stays defined. Use `dims.valid_state` for π0.5 `rs` (dims 8..31 are exact zeros) and hash only dims :7 (GR00T padding is noise).
- **A policy question for the owner**: `tail_passthrough` (execute the previous chunk's steps 5–9, i.e. replan-10 for one decision) is the fresh-regime ceiling at err .21–.28 without any retrieval; it is not a library action, so I list it as a reference row only.
