# R1 选题（2026-09-26，协调者）

构思原文见 `NOTES_ideation_A.md`、`NOTES_ideation_B.md`，诊断脚本在 `diag_A/`、`diag_B/`。

## 两路构思的共同结论（都经过实测）

1. **最强的信号是上一个动作块中没执行完的后半段。**
   - 上一步推理出的动作块只执行了前 5 步，剩下的"尾巴"就是策略对接下来 5 步的计划。
   - 用这段尾巴去库里匹配各条目动作块的开头（35 维），inf 组的误差从 0.47–0.54 降到 0.25–0.29，AURC 降一半，还低于现役库上的 oracle。
2. **离线数据只覆盖两种极端状态。**
   - inf 组的每一步，前一步都是 MISS（尾巴新鲜，来自教师）；cache 组的每一步，前一步都是 HIT（尾巴陈旧，来自库）。闭环里两者交替出现。
   - 在陈旧状态下，连续性匹配退化成"沿库轨迹往下走"，拿不到收益。
   - ⚠ 此时连续性距离几乎为 0，如果拿它当置信度，会虚高，导致一路开环回放。**所有方法都必须区分这两种状态**，陈旧状态下的置信度要来自观测（state 或 vision）。
3. **pooled vision key 对动作的判别力很弱。**
   - 修正归一化（按任务标 μ/σ、线性 z、乘积或取最小融合、白化）后，err 变化 ≤ 0.012。
   - 只用 state 加动作连续性、在 10 倍库上检索，8 个格子全部胜过 B0，每条目只要 32–236 B，B0 是 262 KB。
4. **top-k 合成是通用的改进**，−4% 到 −8%。两个 agent 对取均值还是取中位数加夹爪投票的结论相反，本轮两种都测。
5. **B0 的 top1 与 top2 差距是反向信号**：差距大，说明选中的是一个孤立候选，反而更可能错。
