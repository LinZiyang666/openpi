# Round 6 分析（fable）— 为什么门控跟随在 GR00T 上亏 9–15 个点，在 π0.5 上不亏

数据：round 5 的服务器决策日志 + journal（`r09_fable_r5`，init 20–29，解析时按 init 过滤）；离线对照用 R8 纯缓存臂的延迟策略影子（init 0–29）。
工具：`round6/tools/follow_analysis.py`（播出块分析）、`round6/tools/follow_offline.py`（离线三种候选块 vs 策略）；输出 `round6/out/`。

## 一句话结论
跟随块本身没有问题，问题是**跟随把"第一次叫策略"推迟了**：GR00T 守卫+修正堆叠唯一的兜底是"没进展"守卫，而跟随块让看一眼变少、看到的状态又更贴库，
守卫因此晚 5 个决策（≈ 25 个控制步）才第一次叫策略；GR00T 的失手（抓空、放偏）等不了这么久。π0.5 堆叠多一层"落后就一直叫策略"的升级兜底，输掉的集里第一次叫策略只晚 0.5 个决策，所以不亏。
只开状态阈值的跟随（fv）另有直接伤害：44 % 的跟随块落在夹爪事件 2 行以内、8 % 的跟随块里夹爪翻转，83 % 的第一次叫策略紧跟在跟随块之后。

## 证据
### 1. 播出的跟随块本身不差（反而比重新看一眼"顺"）
| 指标（init 20–29） | π0.5 fg | GR00T fg | GR00T fv |
|---|---|---|---|
| 跟随块份额 / 每集数 | .169 / 9.6 | .128 / 8.1 | .220 / 14.3 |
| 接缝（盲块末控→跟随块首控，RMS 动作）| .061（普通盲块 .025，重新看一眼 .072）| .038（.019，.071）| .043（.019，.088）|
| 跟随后那次看一眼：离库距离 dnn / 落后 lag | .132 / −.43（普通盲块后 .169 / −.77）| .127 / −.35（.169 / +1.35）| .145 / +.29（.300 / +6.0，剩余的普通盲块后看一眼是守门拒绝过的难点）|
| 跟随块里夹爪翻转 | 0 / 960 | 0 / 808 | 114 / 1428 (8 %) |
| 跟随块距夹爪事件 ≤ 2 行 | 0 % | 0 % | 44 % |
| 状态阈值余量（中位数，占半径）| .055 | .065 | .093 |
离线（R8 影子，init 0–29，到策略块的 RMS）：GR00T 门通过层 新看一眼 .119 / 锚点尾块 .123 / 后继块 .121（+.005 / +.003）；π0.5 门通过层 .126 / 后继块 .139（+.013）。
即 GR00T 实际播的"锚点尾块"（os_sf_source 1，H=16 的 10:15 控制）离策略只比新看一眼差 +.005，比 π0.5 的后继块（+.013）还近；库内一致性 |尾块 − 后继²头| = .070（盲块 .048）。
"锚点尾块更陈旧"的假设**不成立**为主因。

### 2. 亏损集中在"守门经常不放行"的集，不紧跟在跟随块之后
| 按守门放行率三分（每集看一眼里放行的比例） | GR00T fg SR vs 对照 | π0.5 fg SR vs 对照 |
|---|---|---|
| 低放行层（n=35 / 34） | **.457 vs .771** | .735 vs .794 |
| 中层 | .935 vs .935 | .970 vs .909 |
| 高放行层 | .971 vs .912 | 1.000 vs .939 |
GR00T fg 输掉的 18 集：守门放行率 .22，平均只播 7.3 块，却叫了 27 次策略仍失败（跑满 104 步上限）；对照同集 6 次调用就成功。
"第一次叫策略前 2 个决策内有跟随块"：fg π0.5 .295（机会水平 .31）、GR00T fg .312（机会 .24；输掉的集 .167）→ 跟随块不是即时导火索；fv .833（机会 .39；输掉的集 .833）→ fv 是。

### 3. 兜底被推迟：第一次叫策略的时间（同集配对）
| 臂 | 第一次叫策略（决策序号）臂 vs 对照 | 输掉的集 |
|---|---|---|
| π0.5 fg | 21.6 vs 18.2（+3.4，中位 +1） | 17.5 vs 17.0（**+0.5**） |
| GR00T fg | 17.7 vs 12.5（**+5.2，中位 +4**） | 17.6 vs 13.4（+4.1） |
| GR00T fv | 22.1 vs 12.7（+9.4） | 22.2 vs 11.7（+10.5） |
机制链：跟随 → 看一眼变少（.50 → .44/.39）且跟随后的看一眼更贴库（dnn 更小、落后更小）→ "没进展"记忆更晚累积 → 守卫更晚第一次叫策略；
GR00T 堆叠只有这一道兜底（无升级），所以晚叫 = 失败；π0.5 的升级看的是检索落后量，在输掉的集里几乎没被推迟（+0.5）。
对照组本身也说明兜底的重要性：两模型对照里"0 次调用的集 100 % 成功、≥1 次调用的集 .87"，即一旦进入难段，成败全看兜底来得及不及。

## 推论（不在本轮冻结）
- GR00T 上门控跟随要可用，必须补一层不依赖"停住"的兜底（例如 π0.5 那种落后量升级的 GR00T 版，opus 的 EscalateOnlyNPGroot 已有类但 round 2 实测 −5），或把跟随后那次看一眼的守卫判据收紧；单靠阶段门不够。
- fv 的伤害机制不同（夹爪事件处盲播），阶段门必须保留。
- π0.5 上跟随安全的前提是升级兜底在；若今后拿掉升级，需重测跟随。
