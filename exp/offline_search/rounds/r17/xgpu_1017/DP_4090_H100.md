# DP：4090 ↔ H100 正式并发路径对照（2026-10-18）

**结论：本轮动作检查未达到预注册等价标准。** 四次运行均COMPLETE，但同卡并发漂移本身已经超过独立硬预算；跨卡又有7个逻辑请求超出各自5×同卡floor。可观测缓存离散决策全部一致，尚不足以认证缓存系统或闭环SR等价。不能由这些动作差直接推断SR下降。

## 1. 身份、总体与传输

| GPU | 两次独立冷启动 UTC | 每次请求 / 拓扑 | MPS生命周期耗时 | 启动驻留（非峰值） |

| H100 | 11:12:15、11:14:21 | 4,608；R4/B8，48客户端 | 124.06 / 121.79s | 均5,916MiB |

每次含2轮×2组×48客户端×24 delivery。每卡4轮，同卡每个逻辑请求比较6对，跨卡比较16对；每组1,152逻辑请求，总计2,304，实际总delivery为18,432。这些是三帧真实观测的协议压力重复，**不是18,432个独立环境样本，也不是物理闭环**。

四次serving PIN均为`59b1b483…ecd39`，runtime均为`5927a753…fa1e`，bootstrap为`4e07fb3e…e4f5e`，harness为`8498998d…a1096`，input为`5361e283…91997`；独立cache文件前后SHA收据全部PASS、identity均`39fda405…0123`。pure/cache native bundle ACK身份也相同。全部16个resident通过原生CUDA graph自检，B1…B8均预热，随后每个resident实际访问B8（每次50–61个B8 ledger事件），动态batch包含B1…B8。逐请求seed相同、全18,432条记录的decision/env时钟与ACK一致、gripper wire符号没有翻转。

两台机器的负载条件不同：4090启动前已有5个后台GPU context，H100两次均无后台context；收据记录这些context均被保留。性能差和batch组成差不能只归因GPU架构。

按[既定单向传输方案](COMMANDS.md)，仅将已COMPLETE的4090结果18,500个文件、211,477,280 bytes，经只读窄模块`xc_local_results`、单流`--bwlimit=16384`送到H100。比较器在H100 CPU运行，逐记录校验JSON与NPZ SHA；H100原始结果保留原处，没有新建反向服务或使用SSH/tether push/pull/expose。通过只读`tether exec cat`取得152,234-byte分析收据，保存在本地 [完整摘要](evidence/dp_4090_h100_summary_20261018.json:1)，其中绑定四次RUN/attestation/cache/harness收据SHA。详细逐请求报告留在H100的`/home/exouser/xgpu_1017/evidence/cross_4090_h100_dp.json`，其SHA由摘要记录。

## 2. 层(a)：动作与并发噪声底

预注册要求：每个请求的跨卡max-abs和relative-L2均≤`max(1e-6, 5×该请求两卡同卡floor的较大值)`；此外max-abs≤**0.000345707**、relative-L2≤**0.001**。不得把同卡floor的增大解释为允许上调硬预算。

| 组 | 4090同卡 max-abs | H100同卡 max-abs | 跨卡 max-abs | 跨卡超硬预算 | 超5×floor |
|---|---:|---:|---:|---:|---:|
| pure，K100/C5 | 0.0007492304 | 0.0004336834 | 0.0009070635 | 433 / 1,152 | 1 / 1,152 |
| cache，n50/C10/knob-off | 0.0010988712 | 0.0013872385 | 0.0014218092 | 346 / 1,152 | 6 / 1,152 |
| 全部 | **0.0010988712** | **0.0013872385** | **0.0014218092** | **779 / 2,304（33.81%）** | **7 / 2,304** |

| 最大 relative-L2 | 4090同卡 | H100同卡 | 跨卡 |
|---|---:|---:|---:|
| pure | 0.0004759011 | 0.0003303940 | 0.0006328772 |
| cache | 0.0006444161 | 0.0010824012 | 0.0011321572 |

同卡自身超绝对预算：4090为163/2,304，H100为110/2,304。H100另有10个逻辑请求超relative-L2预算，跨卡为8个，均已包含在绝对预算失败数中。按逻辑请求最坏误差计算的max-abs第99百分位：4090 floor 0.0006769633、H100 floor 0.0008560789、cross 0.0009069443；这是请求级最坏值分布，不是全tensor元素的百分位。

7个超floor请求全部仍低于硬预算，因而两类失败不是同一集合。具体是1个pure请求及3个cache head与其tail：例如cache client3/seq12，两卡各自4轮动作完全一致，但跨卡差0.0002410412，不能用别的请求较大的floor掩盖它；对应最近邻候选仍远离观测到的top2边界且top1一致。见 [逐项记录](evidence/dp_cross_outside_floor.json:1)。

原生batch metadata进一步区分：client3/seq12的stage1在4090四轮均B2、H100四轮均B1，存在稳定的跨主机batch差；client19/seq18两卡均B1，跨卡仍差0.0000691414；client31/seq18两卡均B2，仍差0.0000713468。前者不能单独归因GPU，后两者也不能仅靠batch size不同解释；完整成员、历史cache状态及stage1中间张量尚未固定对照。这里的B1是R4/B8正式并发调度实际形成的batch，不是另跑单请求staged screen。见 [七个请求的原生batch收据](evidence/dp_floor_outliers_batch_composition.json:1)。

本轮比较的是完整wire action chunk；未记录并发路径的全部prefix/denoise tensor和实际native noise tensor。因此已足以拒绝本轮动作筛查，尚不能定位首个浮点分歧算子，也未完成原定层(a)的全部内部张量覆盖。

## 3. 层(b)：缓存决策与阈值

| 项目 | 同卡四轮 / 跨卡全部组合 | 覆盖边界 |
|---|---|---|
| hit/source、decision/env时钟、seed、NFE、commit C | 2,304/2,304一致 | pure全MISS；cache全FULL_HIT；没有cache fallback MISS |
| top1、完整donor顺序 | 576/576 cache head一致 | 不重复计tail为独立近邻查询 |
| corrector applied | 576/576 head一致 | 528个True、48个False；两条ramp margin均在观测band之外 |
| stall | 576/576 head状态一致 | 全inactive，原因为参考episode仅3个；没有active stall gate证据 |
| periodic knob | 576/576 head一致 | 全False，本配置knob-off；没有active periodic call证据 |

以相同donor ID对应距离估计边界band：48个cache head在近邻边界附近、528个在观测band外，均无top1翻转。附近最大动作差0.0014218092，band外仍有0.0004092455，说明离散决策一致不保证连续动作满足预算。该band仅约束已观测top2候选；缺失stall连续margin仍为unknown。原生stall诊断见 [样例](evidence/dp_cache_head_example.json:1)。

经验一致率100%达到≥99.9%的点估计目标，但576个逻辑head来自三帧重复，并非2,995个独立查询；还缺active stall、active knob和cache MISS分支。层(b)结论是**已观测分支一致、完整资格未完成**。

## 4. 环境和下一步

所有resident报告相同Torch2.7.1/CUDA12.6/cuDNN90501、NumPy1.26.4、cuBLAS12.6.4.1；matmul precision=highest、matmul TF32=False、cuDNN TF32=True、benchmark=False、deterministic=False、CUBLAS_WORKSPACE_CONFIG未设。Python为4090的3.11.15/H100的3.11.16；driver为595.91.07/595.99.02；CPU分别是E5-2696 v4/Platinum8468。包版本相同不是完整wheel二进制或实际kernel dispatch相同的证明。

当前可检验解释是batch组成/shape相关的浮点算法变化，以及不同GPU/driver的kernel实现；cuDNN TF32仍开，是优先消融项。highest已启用、matmul TF32已关闭，单独重复这两个设置不会隔离新因素。这里没有已证明的根因或“恢复等价”配置。原生graph B1自检通过并未消除正式并发漂移。

H100忙时可先执行保持R4/B8的DP `--numerics tf32_off`：请求8GiB空闲，预计5–10分钟、watchdog15分钟，独立冷启动两次；TF32-off峰值尚未实测，8GiB是准入请求，不是硬显存隔离。其余顺序保持原计划。下一模型为Fast-WAM实际4090 `fw4090_reduced` profile：两卡均R2/B16、32客户端，需要42GiB空闲，每次预计8–15分钟、watchdog35分钟。它比H100 full profile的70GiB需求小，但仍不能在不足42GiB的空闲中启动，也不能靠缩R冒充原拓扑证据。精确命令见 [COMMANDS](COMMANDS.md:5)。
