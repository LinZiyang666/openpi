### P1. `vis_pca_allcand_kmean` — the deployable M8 (stale + step 0 selector)
1. **Pitch.** Two-camera PCA-32 codes, task-centred cosine z-sum + state z over ALL task candidates, kernel-mean-8, step-0 alignment: M8's accuracy at 1/900 of the entry size and ≈ 1 ms.
2. **Hypothesis.** M8's stale gain comes from (i) scoring the whole candidate set with vision, (ii) the 10× library, (iii) averaging several chunks; none needs 32768-d keys (F1: PCA-32 = raw within .004) and the state prefilter of M7 was what threw the gain away. Kernel weighting recovers the mean's robustness while down-weighting off-mode members (F1). Step-0 misalignment (library rows at later steps matched by saturated vision) is a separate −.01…−.03 loss (F2).
3. **Algorithm.** `fit()`: library L ∈ {current, 10×}; PCA basis per camera from `derived/r01/f4_vision/pca/<key>/<biglib>/<f>/{mean,basis,proj}.npy` (use the big-library basis for BOTH libraries — F1 shows ≤ .003 difference, saves the current-library SVD); per task t: codes `P_f[C,k]` (k=32) → subtract the task mean of the codes, unit-normalize; `RS[C,8]`, `HEAD[C,5,7]/σ`, `step`, `ep_len`, `next`. `query(q)`: `x_f = (key_f − μ_f) @ B_f`, centre by task mean, unit; `S = Σ_f z_c(cos_f) + st · z_c(−‖rs_q − RS‖)` (z_c = standardize over the task's candidates; st = 0.5 π0.5 / 3 GR00T, or 1 as a single default); if `q.step == 0`: mask candidates with `lib step > 0`; top-8 by S; `w_i = exp((S_i − S_max)/0.5)`, normalize; action = Σ w_i · chunk_i (full (H,32)); topk = the 8 rows in S order. Confidence: P3 (or interim `z(−dnn) + z(−disp8) + z(−overtime) + z(cos_max v0 + cos_max v1)` with library-fitted scales). Regime-independent; no continuity term anywhere. Tier T1 (PCA is a library-only fit; already computed).
4. **Predicted effect.** Stale: 10× .524–.526 / .454–.460 / .442–.457 / .469 (vs M8 .526/.480/.453/.488, B0 .643/.597/.621/.644); current .581–.585 / .511–.518 / .562–.572 / .533–.544 (vs B0; vs M4 −.004…−.024 on three cells, +.014…+.024 on GR00T-sp). AURC stale with the interim confidence ≈ .32/.30/.31/.33 (10×). Gripper-sign-faithful err is +.012…+.016 above these (F5; same for every mean-k method incl. M8/M4).
5. **Cost / deployment.** bytes/entry = 2·32·4 + 8·4 = **288 B** (+ 10 B step/ep_len/next; PCA-64 = 544 B). Fixed: basis 2 × 32768 × 32 f32 = 8.4 MB + means 256 KB per suite (16.8 MB at k=64). ### P2. `stuck_recovery_pure_cache` — tracked-continuation blend + stuck detector + recovery policy (closed-loop lever)
1. **Pitch.** Break the deadlocks that B0's pure-cache failures consist of: keep the served trajectory in the mix, detect "not moving / overtime / terminal row" with state + vision, and change the selection rule when stuck.
2. **Hypothesis.** 58–80 % of stale error and 90–98 % of long stuck runs sit in failed episodes (F3); there a deterministic selector repeats itself (88–91 %) and B0 re-serves the same row (72–83 %). Offline err cannot show the value of escaping (the trace's states do not respond), but the flags that identify the state are measured and cheap, and the library's failed episodes contain recovery motions (F8: removing them hurts). Blending next(served) into the mean is a measured offline gain (F6) and a closed-loop smoother.
3. **Algorithm (on top of P1).** (a) *Blend*: after a HIT, candidate set = {next(served_row)} ∪ top-7 of P1, kernel-mean with next(served) given weight 1 (i.e. as if S = S_max); if next(served) is absent (terminal row) skip. (b) *Detector*, per decision, all from online data: `stuck_n` = count of consecutive decisions with ‖rs_t − rs_{t−1}‖ < m10 (library 10th percentile of per-decision state motion, per suite) AND cos(code_t, code_{t−1}) ≥ c95 (library 95th pct of consecutive-key cosine; the visual half); `overtime` = step / median ep_len(task) > 1.0; `terminal` = served row has no `next` (or progress ≥ .95) while the episode continues; `lag` = step − mean library step of the top-5 > 5. Stuck state := stuck_n ≥ 2 OR terminal OR (overtime AND lag). (c) *Recovery, escalating while stuck*: R1 exclude the library episodes served in the last 3 decisions from the candidate set and re-select with P1 (forces a different trajectory; vision still ranks); R2 after 2 more stuck decisions, additionally restrict to candidates with library progress ≤ (served progress − 0.2) ("rewind": redo the approach — the natural recovery in a grasp/place failure); R3 after 2 more, take the top-1 of R2 instead of the mean (a decisive action rather than a compromise). Reset escalation when motion resumes (stuck_n = 0 for 2 decisions). Everything is library data; no policy call. Tier T0.
4. **Predicted effect.** Offline: blend −.008…−.023 stale err on top of P1 (measured on current; expect similar on 10×); detector flags 18–32 % (overtime), 13–16 % (stuck ≥ 2), 5–22 % (terminal) of stale decisions with err .53–1.11, i.e. it fires on the lost states. Recovery is NOT measurable offline (proxy only: fraction flagged, err there); its value is closed-loop SR on the episodes that currently end in a deadlock (the 17–35 % failed cache-arm episodes with long stuck runs).
5. **Cost.** No library bytes beyond P1 (+ `next` pointer, progress); per query + ≤ 0.1 ms. Per-episode state: last 3 served rows, stuck_n, escalation level, previous rs and code.
6. **Kill.** Closed-loop: SR with recovery not above SR without it on the same suite (paired inits), or recovery causing new failures (knocked objects) in > 3 % of episodes. Offline: blend not ≤ −.005 on 10× stale.
7. **Cheapest diagnostic.** Done for blend and flags (`diag2_*.json`, `agg.txt` B). Next: on the first closed-loop trace of P1, count episodes ending in a stuck run and how many decisions after the first flag the episode timed out (the budget the recovery has).
8. **Variants.** blend weight of next(served) ∈ {as top-1, 0.5}; stuck threshold m10 vs m20; R1 exclusion window 3 vs 5; R2 rewind 0.2 vs 0.4; R3 top-1 vs "largest-motion candidate" (candidate whose head has the largest eef displacement, from library actions).
**Closed loop.** Server keeps the served-row id, previous rs/code, counters; all checks are scalar. Failure modes it introduces: oscillation between two trajectories after R1 (mitigate: exclusion window ≥ 3 and the blend), rewinding into a state where the object is already displaced (R2 uses vision to rank inside the rewound set, so it re-approaches the object where it actually is), gripper flips during recovery (keep the 70 % hysteresis on while escalated). In pure-cache mode every decision remains a HIT; the detector only changes WHICH library action is served.

### P3. `drift_calibrated_confidence` — predicted-err confidence on one scale for both regimes
1. **Pitch.** Confidence = predicted err from {1-NN / window state distance, top-k dispersion, overtime, best v0+v1 cosines, stuck flags}, calibrated on library pseudo-queries incl. failed library episodes; the same units after a MISS (with continuity replacing distance) so one threshold serves both regimes and the stale branch rejects drifted states.
2. **Hypothesis.** B0's confidence saturates at .98 on stuck arms because it is a similarity; the drift/overtime/dispersion signals rank the lost states low (F4: .319/.295/.308/.333 vs B0-score .333/.322/.323/.346; AURC target ≤ .33 met in 3/4 cells, GR00T-l10 .333). The ranking needs no fit (fixed-weight z-sum ≈ cross-fitted linear); the fit is for the scale so fresh and stale share a threshold (R1 §2.6 iv). Failed library episodes (13/64 π0.5, 44/73 GR00T in the 10× libraries) are the only library-internal source of drifted states, so calibrate there.
3. **Algorithm.** Features (stale/step 0): f1 = −d_nn (or −window distance m=3) in units of the library 1-NN median; f2 = −dispersion of the top-8 heads (σ units); f3 = −overtime; f4 = max_c cos_v0 + max_c cos_v1 (PCA space, task-centred); f5 = −stuck_n (capped 5); f6 = −|lag5|. Fresh: f1 = −c0/s_c (continuity of the chosen action), f2 = −dispersion, f4 as above, f3/f5 unused. Calibration: library LOEO pseudo-queries (every row of every episode against the other episodes of its task, GT = its own action; the failed episodes supply the drifted states, prev row supplies the tail for the fresh branch) → isotonic (or 10-bin) map from the fixed-weight z-sum to err, one map per regime, both outputting predicted err; confidence = −predicted err. z-scales are library statistics. Tier T1 (seconds).
4. **Predicted effect.** Stale AURC 10× ≈ .32/.30/.31/.33 (opt .26/.24/.25/.26), current ≈ .39/.35/.36/.39; fresh unchanged (.18–.21 with P4). Pooled one-threshold AURC should match the rank-normalized pooling of R1 (§2.6 iv) instead of the broken .35–.36 of B0-score pairing.

6. **Kill.** Stale AURC on 10× not ≤ M8's B0-score in every cell, or pooled one-threshold AURC (p=.5) worse than regime-wise rank normalization by > .01.
7. **Cheapest diagnostic.** Done for the ranking (agg.txt B). Next: build the failed-episode pseudo-query set and check that its err distribution covers the .7–1.0 range (if not, the closed-loop traces of R2 become the calibration set, held out by episode).
8. **Variants.** window distance vs 1-NN; include libprog5 / terminal flag; isotonic vs binned; per-model vs shared weights.
**Closed loop.** In pure-cache runs the confidence is not gating HITs; it is the scalar that triggers P2's recovery and, later, the HIT/MISS threshold. No extra per-episode state beyond P2's.

## Considered and rejected (with measurements)
- **Flip-aware synthesis** (cluster the top-k by gripper outcome, do not average across the flip; four variants incl. prev-sign prior): +.010…+.015 err vs plain mean, grip mismatch ±.01, gmis at transitions stays .45–.55 for every variant — the candidates are as undecided as the mean; also the mean's gripper already equals the weighted majority sign, and robosuite applies sign() (F5). Keep only the metric caveat: report gripper-sign-faithful err (+.012…+.016) next to the mean err.
- **Success-only / success-weighted library**: hurts in all 4 cells (10× .540/.483/.504/.506 vs .535/.468/.466/.478); failed library episodes hold the drifted-state coverage the stale regime needs (and P2's recovery relies on).
- **Step alignment beyond step 0 / pure trajectory tracking**: |Δstep| windows at steps ≥ 1 cost +.02…+.07 (only GR00T-sp −.012); serving next(served) or the previous tail instead of re-retrieving is +.03…+.08 worse, gating on visual agreement still worse (F6). Only the blend survives (in P2).
- **Mode-seeking synthesis** (largest-cluster mean when the top-5 are multimodal): worse offline everywhere (.98/.84/1.08/.85 vs .85/.73/.92/.73 on the multimodal 9–22 %). RMS rewards hedging, so this can only be judged closed loop; keep as a P2/R3-style option, not a method. Gripper hysteresis: offline-neutral (F5), optional safety only.
