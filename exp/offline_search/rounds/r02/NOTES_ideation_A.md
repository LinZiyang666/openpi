## 1. Proposals (ranked with closed-loop pure-cache success in mind)

### P1 `awm_kernel` — action-whitened joint metric over all task candidates, kernel-16 synthesis, three regime branches (all with vision)
1. **Pitch**: replace "per-field cosine → tanh-z → weighted sum → top-1" by one Mahalanobis metric on [PCA-64 v0, PCA-64 v1, rs8] whose geometry is fitted (closed form) so that visually-and-kinematically near means action-near; return the kernel mean of the 16 nearest chunks. Departs from the frame: no per-field similarities, no normalisation constants, no fusion weights, no top-1.
2. **Hypothesis**: pooled keys carry action-relevant information (R1: PCA-32 ≡ raw, vision worth −.06…−.08 on π0.5 stale) but cosine geometry weights every direction equally, so nuisance variance (layout, lighting, arm pose that does not change the next 5 steps) dominates; on GR00T it dominates completely (0b). Whitening by the covariance of action-similar pairs removes exactly that nuisance; state enters the same metric so its weight is learned, not hand-set (R1: state term hurts π0.5, helps GR00T; the fitted metric gets both right: joint .511/.437/.439/.451 vs vision-only .504/.435/.445/.455 vs state-only .584/.513/.439/.476).
3. **Algorithm** (Method API, `tier="T1"`, stateless across decisions):
   - `fit(lib, ctx)`: `B = ctx.open_library({"pi05":"bpool_cs","groot":"bpool_all"}[ctx.model])` (stored names are accepted in `Result.library`); load the r01 PCA cache `derived/r01/f4_vision/pca/<lib_key>/<biglib>/{v0,v1}/{mean,basis,proj}.npy` with M7's `meta["n"] == B.L` check (or refit with `m7_pca_fit.py` logic); per task t: `X = [proj_v0[:, :64], proj_v1[:, :64], dims.valid_state(rs)]` (136-d), `mean/std` (z-score), heads `H = action[:, :5, :7]/σ` (35-d); pairwise head RMS with same-episode pairs masked → 3 nearest per row → `S_w = mean(diff diffᵀ)`; `W = chol((S_w + 0.1·tr(S_w)/136·I)^-1)`; store `Z_t = ((X−mean)/std) @ W` f32 contiguous, `z2_t = ‖Z_t‖²`, rows, chunks. Early-fit `W0_t` identically on rows with `step ≤ 2`. Continuity scale `s_c` (median 1-NN tail→head RMS across episodes, as M1) and `s_d` (median 1-NN state) for confidence. Also `s_a` = median top-5 dispersion on library pseudo-queries.
   - `query(q)`: `x = [(key_v0−μ0) @ B0[:, :64], (key_v1−μ1) @ B1[:, :64], rs8]`; `z = ((x−mean)/std) @ (W0 if q.step == 0 else W)`; `d = sqrt(z2 − 2 Z·z + ‖z‖²)`. Regime: step 0 or `prev_hit is True` (stale): `f = −d`; `prev_hit is False` (fresh): `f = −d/median(d) − 0.5·c/s_c`, `c = RMS(H − prev_a_exec[5:10,:7]/σ)`. Top-16 by f (stable ties by row); weights `w_i = exp(−((d̃_i − d̃_1)/(d̃_5 − d̃_1))²)` with d̃ = −f; `action = Σ w_i·chunk_i / Σ w_i` (full (H,32), all dims averaged; gripper sign is what is used). `topk = rows[o]`, `scores = f[o]`.
   - Confidence: stale `z(−d1)+z(−disp5)+z(−dst)` (z-scales from library pseudo-queries), step 0 `−disp5`, fresh `−d1/median(d) − disp5/s_a` (or M1's `−c0/s_c − disp/s_a`, which is still better after a MISS: AURC .188 vs .210 .184 .280 .262). Extras: `d1, d1_rel, disp5, dst, regime, still`.
   - `bytes_per_entry() = 136·4` (or 68·4 / 32·4 for the compact variants).
4. **Predicted effect** (measured, big library): stale err .511 .437 .439 .451 (kref 8: .509 .435 .437 .446), AURC .297 .278 .299 .327; step 0 .210 .158 .255 .170, AURC .170 .123 .245 .177; fresh .256 .275 .250 .267; grip .201 .143 .133 .168; regime-mixed estimate (R1 §2.5 formula, p = .5, step-0 weights .046/.017) **.375 .352 .339 .353** vs R1's best combination .389 .376 .346 .376. Current library (fit on the pool): stale .562 .495 .500 .493, step 0 .266 .223 .318 .209. Cost: 544 B/entry (+18.5 MB fixed per suite), 1.1 ms/query CPU single-thread, fit < 30 s per suite.
5. **Tier / deployment**: T1. Library file per entry: `code f16[136]` (or f16[32] rank-32), `action f32[H,7]`, `task_id` (+ `episode, step, next` for diagnostics only); per suite: PCA μ/basis per camera (f16), per-task `mean, std, W, W0`. **Online per decision**: stage-1 encoder as today → pooled 4×4 keys (already computed on every HIT) → two 32768×64 matmuls (GPU µs / CPU 0.7 ms) → 136×136 whitening → distances to ≤ 4.7 k task candidates → top-16 kernel mean (CPU 0.4 ms). **Per-episode state**: none (the step index and `prev_hit` are inputs). **Closed-loop failure modes**: (i) kernel averaging shrinks the commanded translation/rotation by 5–7 % (norm ratio .93–.96 vs B0 1.00–1.07) → slower approach, possible stalls at contact and step-cap timeouts on long l10 tasks; (ii) drifted/stuck states are not recovered (err .62–.79 there, same stay rate as B0); (iii) gripper chatter when the kernel vote is near 50/50 (mean gripper sign flips between decisions); (iv) frequent switching between library trajectories (same-episode rate .44–.62) — smooth in action space because of the averaging, but untested closed loop. Mitigations are P3.
6. **Kill criterion**: on the harness, stale err not ≤ M8 − .01 in ≥ 3/4 cells on the 10× library, or not ≤ B0 − .05 in every cell on the current library, or step 0 not ≤ M8 in ≥ 3/4 cells; or > 3 ms/query at concurrency 1. Closed loop: pure-cache SR not above B0's .668/.452/.736/.468 on ≥ 3 of 4 suites × models after 500 episodes.
7. **Cheapest diagnostic first**: done (scripts above). For the implementation: `harness.smoke` on `pi05_l10_cache` must show err ≈ .44 (5 episodes ≈ ±.05) and flip rate vs B0 > .9; `profile.compare` vs `M8_b0big_k5_mean` (expect win rate ≥ .6, dAURC CI < 0); `profile.breakdown --slices task,third,grip,conf_dec`.
8. **Variants**: `vision_only` (P2 below); codes `full136 | rank64 | rank32` (.510 .433 .436 .451 / .507 .439 .437 .452; rank16 loses .01–.02); λ ∈ {.01, .1}; kref ∈ {5, 8}, k ∈ {16, 32}; state-block scale ∈ {1, 3} per suite (GR00T-sp −.013 at 3); step-0 branch = early fit (`W0`) on/off; fresh fusion λ_c ∈ {0.5, 1}; PCA-64 vs PCA-128 per camera (−.002…−.007).

### P2 `awm_vision_only` — the same metric with no robot state anywhere (the "raw strength of vision" arm)
1. **Pitch**: the cache selects and synthesizes from the two camera keys alone (128-d whitened), no state, no continuity except the fresh-regime fusion term; the cleanest answer to the owner's question and the pure-cache arm most different from B0.
2. **Hypothesis**: after whitening, the visual keys already encode the arm configuration that matters for the next 5 steps (0b); removing state removes the field that misleads the picker in drifted states (state 1-NN is > 3× the library median there) and the field that has to be re-scaled per model. Offline it is ≈ P1 (stale .504 .435 .445 .455: better on π0.5, +.005 on GR00T; step 0 with early fit .210 .158 .282 .227 → the state helps GR00T at step 0 by −.03/−.06, so keep the early-fit branch joint or accept the loss); its value is what it isolates for the owner, plus a smaller entry.
3. **Algorithm**: P1 with `features = [PCA-64 v0, PCA-64 v1]`; everything else identical (fresh fusion, kern16, confidence `z(−d1)+z(−disp5)` without `dst`, AURC stale .338 .300 .340 .363 with −d1 alone).
4. **Predicted effect**: stale .504 .435 .445 .455; step 0 .210 .158 .282 .227 (joint early fit .255/.170 on GR00T — recommend joint at step 0 even in this arm, documented as the only state use); fresh ≈ .256 .275 .250 .267 (vision-only joint distance measured within .001–.006 of joint in the fresh regime). Cost 512 B/entry (f16 256; rank-32 128 B), 1.0 ms.
5. **Tier / deployment**: T1; the library entry has no state; online compute as P1 minus the state concat; per-episode state none. Closed-loop failure modes as P1 plus: with no state term a visually ambiguous scene (occluded wrist camera during grasp) can select a chunk from a different arm configuration → jerk; the `still`/`hit_verify` signals (§3.1) would be the diagnostic to log.
6. **Kill criterion**: stale err worse than P1 by > .01 in any cell, or step-0 err worse than P1 by > .03 (already true on GR00T without the joint step-0 branch) — then it survives only as an ablation row.
7. **Cheapest diagnostic**: done (p6 `vis` rows); closed loop: run it as arm B next to P1 and B0 on one suite first.
8. **Variants**: with/without the joint early-fit step-0 branch; rank-32 codes.

### P3 `awm_closedloop_synthesis` — norm-preserving kernel mean + gripper hysteresis (offline-neutral, closed-loop insurance)
1. **Pitch**: keep P1's selection; change only how the returned chunk is assembled so that averaging does not slow the robot or chatter the gripper.
2. **Hypothesis**: the offline metric rewards the conditional mean (kernel mean −.10 vs top-1), but the mean of nearby chunks is 5–7 % shorter than any member (0e) and its gripper sign can alternate across consecutive decisions. In a pure-cache closed loop these two artefacts, not err, are the likely causes of new failures (timeouts, dropped objects). Direction is what the metric got right (dircos .82–.86 vs top-1 .75–.81), so rescale, do not re-select.
3. **Algorithm**: (i) `a = kernel mean`; rescale `a[:, :6]` per step by `Σ w_i ‖chunk_i[t,:6]‖ / (Σ w_i ‖a[t,:6]‖)` (norm-preserving mean; bounded at ×1.15); (ii) gripper: `g = Σ w_i sign(chunk_i[t,6])`; output `+1/−1` by sign of g, but keep the previously served sign unless `|g| > 0.4·Σ w_i` (hysteresis); at step 0 no hysteresis. Per-episode state: last served gripper sign (reset per episode; deterministic).
4. **Predicted effect**: offline err within ±.01 of P1 (the norm rescale changes err slightly upward on the RMS metric: expect +.00…+.01), grip mismatch unchanged or −.01; closed loop: fewer timeouts/oscillations — unmeasurable offline, hence ranked below P1/P2. Cost: identical to P1.
5. **Tier**: T0 add-on to P1. Library/online compute as P1; per-episode state = 1 int.
6. **Kill criterion**: offline err > P1 + .015 in any cell, or grip mismatch on transition steps > P1 + .02; closed loop: no SR gain over plain P1 on the first suite.
7. **Cheapest diagnostic**: harness run of P1 with `norm_preserve=True/False`, `hysteresis ∈ {0, 0.4}` and `profile.breakdown --slices grip` (transition steps); plus the R1 §4.1 "self-fed" proxy for chatter (count sign changes of the served gripper in runs of HITs).
8. **Variants**: hysteresis threshold {0.2, 0.4}; rescale cap {1.10, 1.15}; apply the rescale only when `d1_rel` is small (confident) to avoid amplifying garbage in drifted states.

### P4 `awm_t2_metric` — nonlinear metric initialised from P1 (T2, only if P1 saturates)
1. **Pitch**: a 2-layer MLP φ: 136 → 64 trained on library pairs so that ‖φ(x_i) − φ(x_j)‖ regresses the head RMS of (i, j) (same task, other episodes), initialised with P1's linear whitening; everything else as P1.
2. **Hypothesis**: the gap P1 → oracle (stale .51 vs .29) and the per-decision best-of bound (.495 .415 .430 .427) suggest residual structure a linear metric cannot capture (which visual directions matter depends on the phase, e.g. the wrist camera only when near the object). R1's InfoNCE heads failed on same-distribution data; a *regression* of action distance with a linear warm start is a different, better-conditioned objective.
3. **Algorithm**: pairs = each library row with its 16 nearest (whitened) rows from other episodes plus 16 random same-task rows; loss = Huber(‖φ(x_i)−φ(x_j)‖ − RMS_ij); Adam, 5 epochs over ~30 k rows (GPU 1–2 min, `--allow-gpu-fit`), CPU inference in `query` (two 136×64 matmuls, µs). Same synthesis/confidence as P1.
4. **Predicted effect**: −.01…−.03 stale if the hypothesis holds; probability ≈ 35 %. Cost: same bytes (64-d codes 256 B), +µs.
5. **Tier**: T2 (must earn ≥ .02 over P1 stale in ≥ 3/4 cells or is dropped; owner: T2 has to earn its keep).
6. **Kill criterion**: above; also any cell where it is worse than P1 by > .01.
7. **Cheapest diagnostic**: fit on one task of `pi05_l10` and compare 1-NN/kern16 err on that task's cache decisions to P1 before scaling out.
8. **Variants**: linear-only (136→64) trained with the same loss (should reproduce P1 within .005 — a sanity check); with/without phase feature (step) as an input.

**Ranking**: P1 (large measured gain in the primary exam, deployable size and latency, wins all 40 task-cells) > P2 (same machinery; the arm that answers the owner's question and the most informative closed-loop contrast) > P3 (no offline gain by construction; protects the closed-loop result of P1/P2) > P4 (speculative, T2). I recommend coding P1+P2 as one family with kwargs (`features ∈ {joint, vision}`, `codes`, `lam`, `kref`, `state_scale`, `step0_early`, `fresh_lam`) and P3 as kwargs on top, so the four coding agents can split variants/ablations; run the closed-loop pure-cache A/B with arms {B0, P1 joint kref8, P2 vision-only (joint step 0), P1+P3}.

## 2. Answers to the coordinator's closed-loop questions (common to P1–P4)
- **Server per decision**: stage-1 vision encoder (as today, both cameras) → pooled 4×4 keys → project (2 × [32768×64] matmul, GPU µs or CPU 0.7 ms) → z-score + 136×136 whitening (per task; `W0` at step 0) → squared distances to the task's ≤ 4.7 k codes → top-16 → kernel weights → weighted chunk (H,32); fresh regime adds a 35-d RMS to all candidate heads. Total CPU 1.1 ms single-thread (measured), well under B0's 1.3–8.3 ms; no policy action inference.
- **Per-episode state**: none for P1/P2 (the step index and HIT/MISS flag are inputs); P3 keeps the last served gripper sign. All arms are deterministic.
- **Library file**: per entry code (f16[136] joint / f16[128] vision / f16[32] rank-32) + action `[H,7]` f32 + task id; per suite PCA μ/basis (8.5 MB f16) + per-task `mean, std, W, W0` (1.5 MB). 27–43 MB per big library vs 431–1,103 MB today.
- **Expected failure modes**: slower motion from averaging (−5…−7 % norm), gripper chatter near 50/50 votes, no recovery from drifted states (identical to B0's weakness; oracle shows the library *does* hold usable chunks there: .23–.41), trajectory switching every ~2 decisions (smooth in action space). Not: oscillation between two far-apart chunks (kernel weights suppress isolated candidates), nor library-size latency (linear in C at 0.1 µs per candidate).
- **Closed-loop expectation**: offline stale err −20…−30 % vs B0 (and .32–.35 on episodes B0 completed, within .07 of the fresh regime), but the protocol (§3.3) records weak offline→SR correlation; I would not commit to a number beyond "P1 ≥ B0 on all four cells is the hypothesis, +5–15 pp SR the hope".

## 3. Considered and rejected (all measured, big library unless stated)
1. **Δ-key "visual motion" retrieval / predicted-motion HIT verification** (query Δ = P(key_t) − P(key_{t−1}) vs library Δ_r = P(r) − P(prev(r)); and cos(Δq, P(next(served row)) − P(served row)) as a "did the HIT do what the library did" check): as a selector stale .603 .562 .503 .564 alone and .551 .507 .491 .520 fused with the absolute cosine (absolute alone .528 .464 .490 .512); fresh .349 .340 .418 .441.
