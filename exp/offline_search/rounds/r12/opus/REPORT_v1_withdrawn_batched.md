# R12 opus 报告：看一半（检索时只用一路相机）

opus，2026-10-03。（子代理写此文件被拦，由协调者按其交回原文代存。）只用差集池示范库和允许的非测试闭环数据：R6 B 池校准录像、R11 开发集日志，以及协调者在 B 池开发起始状态上新录的看图数据。没有读测试集 A 的任何逐局数据，也没有读另一位研究员的目录。预测在 12:15 冻结；开发集数据是冻结之后才读的。

## 给 owner 的结论（白话）

**一、最重要的发现：π0.5 看一半省下的钱，主要来自"相机一路一路编码"这个写法；GR00T 本来就没得省**
- π0.5 现在每看一次图，要把三张图先后送进视觉编码器：第三人称、手腕，还有一张永远被遮住、不起作用的空白占位图。
- 我在本机 4090 上单独测了视觉编码器（只测编码器本身，不是服务全路径）：
  - 一张图 23 毫秒；两张图放进同一次计算 23.5 毫秒，三张 23 毫秒；
  - 两张先后编码 47 毫秒，三张先后 69 毫秒。
  - 显卡一次只处理一张图时根本没吃饱，多放一张几乎不花时间。
- 所以只要把两路相机放进同一次计算、空白图用缓存：
  - 看全的价钱估计从 0.152 降到 0.07 左右，和"只看手腕"一样；
  - 每个决策点的推理开销约降 0.04。例：π0.5 长任务 50 集从 0.167 到约 0.13；定期旋钮追平纯推理的那个点从 0.31 到约 0.27。每次调用大模型也同样便宜一截；
  - 成功率不受影响：一起编码的检索特征只差 0.15%，和换一张显卡的数值差别一样小。
- GR00T 本来就把两张图放在一次计算里。协调者已实测：GR00T 只看一路 0.143–0.150，看全 0.148，看一半没有钱可省。
- π0.5"两路一起编码"在真实服务路径上的价钱还没测，要等本机 GPU 空出来（约一小时）。**建议先测这一项，再决定要不要做看一半。**

**二、只看一路到底差多少**
- 手腕相机是更好的那一路；π0.5 单独用第三人称，误差要大两到三倍。但只看手腕时，缓存给的动作比两路都看平均远 2–6%。
- 试过的补救全部无效：
  - 给单路重新训练距离尺子、调参数、加主成分；
  - 换视觉特征的汇聚方式、降低分辨率重新编码；
  - 加"和上一步连贯"的约束。
- 有用的发现：上一次看图时的第三人称画面（10 个控制步之前）几乎和刚拍的一样好用，说明第三人称里有用的信息变化很慢；再旧（20–40 步）就不行了。

**三、什么时候可以只看一路（按安全程度分段）**
- **不是按抓、放这类动作阶段分。** R7 用的夹爪阶段信号完全预测不了只看手腕会不会出错。
- 能预测的是看完手腕之后的自检：把手腕画面和上一次的第三人称画面拼起来再检索一次，看答案变不变。不变就可以只看手腕，变了就补看第三人称。
- 安全的时刻集中在一局的前段：前五分之一里 66–82% 安全，最后五分之一只有 33–48%；注定失败的局里更少。长任务后段要靠第三人称分辨"哪一步已经做完"。
- 必须看完手腕再判断。只凭上一次的结果提前决定，同样多的只看手腕会多出一倍误差。

**四、如果仍然要做看一半：安全做法和能省多少**
- **做法：**先只看手腕，自检通过就直接用；自检不通过，或手里的第三人称画面已超过 40 个控制步，就补看第三人称，照现在的方式决策。调用大模型时照常补齐两路。
- **容忍度：**只由示范库大小决定（库越大越严），与任务无关。
- **开发集闭环核对**（B 池开发起始状态，每组 100 局）：
  - 按我冻结的容忍度，π0.5 长任务 50 集有 55% 的看图只用手腕，但放进来的误差是库内预计的 3 倍。
  - 收紧到三分之二后约 40% 只用手腕，误差回到目标以内（约相当于 0.15 个点成功率）。
- **能省多少：**按现行价目每个决策点省约 0.02–0.03，但其中六到八成其实是"补看一路比看全便宜"，也就是省掉了那张空白图；真正属于看一半的只有 0.003–0.01。
- **激进做法**（除调用大模型外每次都只看手腕）：省 0.03–0.04，但预计掉 0.6–0.8 个点；用第四层旋钮补回来要花的开销和省下的差不多甚至更多。**不建议。**

**五、建议的实验顺序**
1. **第 0 步**（协调者，本机 GPU 空闲时）：实测 π0.5"两路一起编码"的第一阶段耗时。冻结规则：不超过"只看手腕"的 1.25 倍，就采用一起编码，π0.5 不做看一半。
2. **开发集小跑**（每组 50 局）：一起编码与原系统同批对照，只核对实现、价钱和"首步检索一致率 ≥ 0.9"，不调任何参数。
3. **测试集**（每组 500 局，同批对照）：
   - 一起编码在 π0.5 五个格子上与原系统比较，外加两个开旋钮的格子；
   - 若仍做看一半：同样五个格子，外加"每次只看手腕"两组作校准，以及"把省下的开销花在多调大模型上"的同开销对比。

**六、需要你裁定**
- "两路一起编码"改的是服务程序的第一阶段，不是缓存层。是否接受这类改动？
- 若接受，推理开销价目要按新实测价重定。是否同时换基准？纯推理本身也会便宜约 8%。
