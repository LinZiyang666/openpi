## 0. TL;DR

1. **N1 独占高精度区**。能达到的最小 `lost%`:N1 **0.4–0.7%** / sticky-K 1.1–2.3% / periodic 30.7–39.4%。连续 `cp1_score` 让 N1 进入 `lost≤1%` 的操作区,而只用二值 MISS 历史的 sticky 与 verdict 盲的 periodic **结构性进不去**——这正是 roadmap F1(prev_score AUC 0.98 ≫ prev_is_MISS 0.92)的可操作兑现。
2. **同预算(同 skip%)N1 全面更省**。skip≥10/15/20% 时 N1 的 dInf **逐点 ≤ sticky**、且远小于 periodic(0.18–0.36)。roadmap 及格线「同预算打败 periodic」**离线决定性达标**,并顺带压过 sticky 计数前沿。
3. **两个 live 操作点已选定(每 suite)**:**A 近免费**(lost≤1%)skip 10–20% / dInf 0.002–0.005;**B 平衡**(lost≤4%)skip 17–32% / dInf 0.011–0.028。B 的 skip 达 oracle 上限的 **85–95%**。
4. **C9 三档延迟判决精确复现**:net@4ms(优化小库)≈0/微负、net@34ms(stock)正、net@70ms(50k 库)强正。**miss-skip 型 N1 的延迟价值只在 stock/大库/远程档兑现**,优化小库档不值得(与 roadmap F6/C9 一致)。
5. **距 oracle 缺口 = prev-score 预测的价格**。A 点摘到 oracle skip 的 48–59%(近零 lost),B 点摘到 85–95%(4% lost);最后几个百分点的 skip 需要付出快速上升的 lost。缺口来自 AUC 0.98(非 1.0)的一步延迟预测 vs 完美前视。
6. **变体 B(WS-aware probe:落 WS 带时 probe 间隔减半)在 A 点 7/7 零增益** → roadmap 开放问题 §6.3 得解:高精度操作点不需要 WS 单独一档,不值得增复杂度。

## 1. 方法与口径

**N1 状态机(离线逐 episode 重放)**:寄存器 = 最近一次搜索步的 `cp1_score`;`SEARCHING` 每步搜索,连续 `j` 个已搜索步 `score < θ_low` → 转 `SKIPPING`(该步走全推理);`SKIPPING` 每 `M` 步 probe 一次真搜索,probe `score ≥ θ_high` → 恢复(双阈值滞回防抖)。θ 锚定各 config 自己的 `(ws_thr, fh_thr)`:令 `g = fh_thr − ws_thr`,`θ_low = ws_thr + lo·g`(`lo∈{−0.5,−0.25,0,0.25,0.5,1.0}`),`θ_high = θ_low + band·g`(`band∈{0,0.5,1.0,1.5}`),`j∈{1,2,3}`,`M∈{3,5,8,None}`。阈值由数据反推(判据在 score 上单调:`ws_thr`=最小非-MISS 分数,`fh_thr`=最小 FH 分数),与 yaml baked 值一致。

**指标**:`skip%`=跳过搜索步/N(probe 步算搜索);`lost%`=被错跳的真命中步(FH/WS)/N;`dInf`=精确 inf_ratio 增量 = (1/N)Σ_{错跳命中步}(1−inf_value),`inf_value`={FH:0, WS:warm_cost(start_t)=1−0.5(1−t), MISS:1};三档净值 `net = skip%·SEARCH_MS − dInf·INFER_MS`,`SEARCH_MS={4,34,70}ms`,`INFER_MS=300ms`。

**反事实口径(roadmap C8)**:跳真 MISS 步动作不变 → 精确;错跳命中步把缓存回放换成新推理 → dInf 是"冻结 verdict 序列"的一阶近似,SR 只能 live 测。**故 A(lost≤1%)离线最可信,B(lost 4%)有真实反事实暴露,1b 用于检验其离线 dInf 是否成立。**

**内建 Verify(断言全过)**:`oracle skip% == 数据 MISS%`;所有操作点 `skip/lost/dInf ≥ 0`、`lost ≤ skip`;`band=0` 退化为单阈值门。脚本正常跑完两 suite = 断言无触发。

## 5. 判决

- **N1 vs sticky(roadmap 主张"支配 sticky 前沿")**:✅ 成立且更强。不只是同 skip 更省 dInf(§2/§3 对撞表),而是 N1 **打开了 sticky 到不了的 lost≤1% 精度区**(sticky 最小 lost 1.1–2.3%)。计数规则的信息上限(binary 0.92)结构性低于连续分数(0.98)。
- **N1 vs periodic(及格线)**:✅ 决定性。同 skip 下 periodic dInf 高一到两个数量级(0.18–0.36 vs N1 0.002–0.03)。verdict 盲的周期门在这个任务上不构成竞争。
- **C9 三档延迟(miss-skip 族)**:优化小库(4ms)A 点净值 ≈0(−0.9~+0.3)、B 点负;stock(34ms)A 点稳定正(+2.8~+6.4);50k 库(70ms)A/B 均强正(+6.4~+19.2)。**结论**:当前优化小库档 N1 的价值主要在"省搜索的 kNN 计算"而非闭环延迟;**延迟收益要 stock/大库/远程 backend 才显著**。这与 roadmap 一致,并给 1b 的部署档选择提供依据(见 §6)。
- **距 oracle 缺口**:A≈oracle 的 48–59%、B≈85–95%。缺口是一步延迟预测(AUC 0.98)相对完美前视的固有代价,不是实现缺陷。要再逼近需引入更多历史(last-k)或标定(押后 Stage 3 C1)。
- **变体 B(WS-aware probe)**:7/7 零增益,砍掉。高精度操作点的停搜段很短,probe 几乎不落在 WS 带,减半间隔无处发挥。

## 6. 给 Stage 1b 的交接

1. **每 suite 两个 live 操作点**:**A 近免费**(离线最可信,lost≤1%,首选安全点)与 **B 平衡**(lost 4%,摘 85–95% oracle skip,专门用来检验离线 dInf 在 live 是否成立)。具体 (lo,band,j,M) 见 §2/§3 表——per-config 标定,libero_10 fh5_ws40(MISS 37.9%)可摘量最大。
2. **及格线**:同 skip% 下 live SR ≥ always_search − 1pp(A 点尤其应几乎无损),且同预算 ≥ periodic。B 点重点看 SR 是否随 4% lost 明显退化(C8 反事实检验)。
3. **部署档报告**:live 延迟按 C9 三档报;若 1b 只在优化小库档跑,预期延迟净值 ≈0,**价值论证应落在"省 kNN 计算/未来大库外推",而非当前闭环墙钟**。
4. **落地路径**:exp 层 `ClientControlledGate`(客户端已有 `__hit_meta__.cp1_score`,零 src),N1 状态机逻辑放客户端 runner;server 侧维持 always_search 采集口径以便对齐。G0a hook 服务器化为捎带项(Stage 1c),不阻塞 1b。
5. **WS-aware / 更激进档**:离线已否掉 WS-aware;若 1b 想要更高 skip,沿 §2/§3 前沿向下取点即可,不需新机制。
