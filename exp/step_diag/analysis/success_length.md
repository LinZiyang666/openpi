# 成功轨迹长度：warm start / warm reset / 纯减步 vs full（RoboCasa365，13 任务）

> 2026-09-23。数据 = §6.5 / §6.6 / §6.8–6.11 的 macro-13 各臂（seed 2,000,000+idx，out root `rc` + `rc_macro13`）。脚本 `exp/step_diag/analysis/success_length.py`，产物 `data/analysis/success_length.json`（`env_steps` 与 `decisions` 两种口径；bootstrap 20000，seed 20260923）。

**口径**。长度 = 被接受那次 attempt 的 `episode_summary.n_env_steps`（环境步；每次决策执行 5 步）。只看成功集（失败集跑满上限，长度无意义）。π0.5 另有逐决策行，逐集核对连续且计数一致；GR00T 只有 summary，核对 5(n_dec−1) < n_env ≤ 5·n_dec。三组全部通过，0 条剔除。

- **配对**（主读法）：同一环境身份 (task, init_idx) 上 **该臂与 full 都成功** 的集，逐任务取 (臂 − full) 均值，再 13 任务等权平均；区间 = 任务内按身份 bootstrap。这样两臂比的是同一批初始状态，不受「谁在更难的集上成功」的选择偏差影响。
- 比值 = 逐任务（臂成功长度均值 ÷ full 成功长度均值）的等权平均。「更短 / 更长」= 配对集里该臂更短 / 更长的比例。
- 同一身份跑过两轮的格（CloseFridge / PnP 的 warmreset 等）取两轮成功长度的均值。

## 读法

1. **π0.5：warm reset 的成功集明显更短，而且 13/13 个任务都更短。** 快照或最终动作在 t=1 喂入（T=0.2 或 0）比 full 少 97–110 环境步（约短 23–26%，配对集中 88–92% 更短）；最终动作喂在 t=0.9 少 157 步（约短 38%）。纯减步反而长 33 步（+7.5%），我们的精确续跑与 full 无显著差别。
2. **GR00T：基本不变，只有小幅、方向不一的差别。** t=1 喂入（T=0.25 快照或 T=0）N=1 时反而长 22–31 步（+7–9%，显著），我们的精确续跑也长 19–25 步（+6–9%）；喂在 t=0.75 / 0.5 与 full 无差别；N=2 时最终动作起点的三种 warm reset 短 13–28 步（−4 到 −7%），其中 T=0、t=1, 0.5 最明显（−28 [−41, −16]，9/13 任务更短）。
3. **和 init_probe 一致。** π0.5 在 t=1 喂入时输出保留了大部分缓存差异（§6.10），而缓存库由教师的成功轨迹建成，成功集就更像「照着一条成功示范走」，所以更快；GR00T 在 t=1 基本抹掉缓存，长度也就回到 full 附近。这是机制上的一致性，不是因果证明。
4. **对成本的含义（π0.5）。** 成功集每集决策数少约 1/4，叠加每次决策 2 次前向对 10 次，warm reset 在成功集上的动作头（action expert）总前向次数约为 full 的 0.2 × 0.75 ≈ 15%；VLM 前缀（stage 1/2）每次决策照跑，只按决策数省约 1/4。失败集的长度不变（跑满上限），所以按全部集算的节省小于这个数。

**局限**：只比较成功集；配对集数按臂 123–336，个别任务（CloseBlenderLid、OpenStandMixerHead 等低成功率任务）只有 1–7 对，逐任务数字噪声大，只看宏观和任务计数。
