# RoboCasa365 种子解剖：每个任务由什么组成，seed 到底改变什么

> 状态：**定稿**（2026-08-22；教师基线于 2026-08-23 随 T5b 库扩容全量重算，见 §3 列定义与 §3.0b）。全部定量数据来自实测探测，方法见 §6。
> 动机：权重搜索里发现 4 个 PickPlace 任务纯 cache 全配置 ~1.5%，追查后发现 **eval 的每个种子会整套重抽物体类别/位置/干扰物**——这份报告把 13 个评测任务逐一解剖：seed 影响什么、不影响什么、对 cache 检索意味着什么。
> 证据文件（同目录）：`pickplace_first_frames.html`（库 vs eval 首帧三相机对照页）、`ws_search_matrix.html`（132 格 × 13 任务成功数热力表）、`ws_object_probe.json`（死任务物体类别探测）、`ws_anatomy.json`（全任务关节/位置/指令探测）。

## 0. TL;DR

- **场景（厨房本身）不由 seed 决定**——我们显式钉死 `layout_and_style_ids=[(1,1)]`；seed 决定的是**这一集里"活的"那部分**：被操作物体的类别与实例、所有可动物体的摆放、台面干扰物集合、家具的初始关节状态、以及（随物体而变的）语言指令。
- 同 (task, seed) ⇒ **逐字节相同的初始状态**（这是配对统计检验合法的根基）；采集用 seed 0…N-1，eval 用 1,000,000…——两族**永不相交**。
- 任务分两类：**固定家具类**（关冰箱/开抽屉…目标位置恒定，seed 只改连续量与干扰物）与**抽样物体类**（PickPlace…目标本身被重抽）。cache 检索在前者有真实梯度，在后者被"n=5 库只覆盖 19% 类别"卡死。

## 1. seed 的语义链条（代码级，已亲验）

1. **eval/采集统一公式**：`seed = base_seed + orig_init_state_idx`（`exp/robocasa365/episode_runner.py:367`）。采集 `base_seed=0`（h5 的 `episode_id` 即 seed 偏移）；eval `base_seed=1_000_000`（plan D-E 段）。
2. **reset 一次性消费 seed**：`env.reset(seed=k)` 驱动本集全部随机化抽样；同 k 完全可复现（本报告全部探测即基于此复现采集/eval 的初始状态）。
3. **场景与 seed 解耦（关键陷阱）**：RoboCasa 官方语义里 kitchen 场景由 seed 抽取（`kitchen.py:595` seeded `rng.choice`）；本实验用 `layout_and_style_ids=[(1,1)]` 显式钉死，所以**绝不能**用挑 seed 的方式控制场景，也因此下文所有 seed 效应都不含"换厨房"。
4. **物体实例池**：`obj_instance_split="target"`、`split=None`——物体从任务的 target 实例池抽，不随场景切换换池。

## 2. seed 影响清单（全任务归纳）

| 维度 | 是否随 seed 变 | 备注 |
|---|---|---|
| 厨房结构（柜体/家电布局、材质） | **否** | 由 layout/style 钉死 |
| 相机位姿 | **否** | 同一 layout 下固定（对照帧逐像素同位） |
| 被操作物体类别/实例 | **视任务**（§3 逐任务） | PickPlace 族每集重抽；固定家具族无此概念 |
| 物体初始位置 | 是 | 自由体坐标逐 seed 不同 |
| 台面干扰物集合与摆放 | 是 | 所有任务都有 |
| 家具初始关节状态（门角/抽屉行程等） | 是（连续量，仅与任务目标相关的那一个关节） | 实测：CloseFridge 全场 37 个家具关节里**只有冰箱门铰链**随 seed 变（81°–90°，~9° 窗口）；OpenDrawer/Faucet 的目标关节恒起始于闭合位 |
| 语言指令文本 | **视任务**（§3 分类） | 4 个 PickPlace 每集换物体名；OpenDrawer 左/右、DishRack 推入/拉出、OpenCabinet 单/双门三个二值任务；其余 6 个恒定 |
| 机器人基座位置 | **否** | 13 种子基座坐标逐位相同 |
| 机械臂初始 qpos | **是（小幅抖动）** | 7 关节各 ±2.5–4.6°（robosuite 初始化噪声）——腕部相机视角与 robot_state 向量因此逐集微变 |

## 3. 任务档案（13 个）

> 列定义：**teacher** = **采集战役实测**（同场景 (1,1)，括号内为总尝试数）——教师在评测场景的最可靠基线。数值已于 2026-08-23 随 T5b 库扩容（每任务 50 条成功）**全量重算**，样本量从 n=26–100 增至 **n=64–233**；准入门的 n=5 切片仅作历史参考（粒度 ±0.2，曾造成 TurnOnSinkFaucet「场景A 0/5 vs 采集 0.26 vs 场景B 4/5」的小样本假象）。**cache 均值/峰值** = 132 个 complete cell 的任务级均值与最好 cell（8 trials/task；峰值经 132 次选择，读作"好权重区的上界"而非无偏点估计）。**指令** = 13 个探测种子的指令变体数。

**梯度即结论**：cache 表现随"目标确定性"单调下降——固定家具 ≫ 二值变体 ≳ 类别恒定的可动物体 ≫ 类别重抽。指令变体数就是每个任务"目标被 seed 重抽的自由度"的直读指标。

**正面发现：CloseFridge 上纯 cache 反超教师**——教师采集期同场景 51/124=**0.41**，cache 全矩阵均值 0.481、好权重区 0.75–0.88（约 2×）。TurnOnSinkFaucet 为弱化版：教师 61/233=**0.26**，cache 均值 0.21 略低、好权重区 0.50（约 2×）。机理：重放一条已验证成功的轨迹，规避了教师现场推理的失败模式。其余固定家具任务（Drawer 0.78 / Mixer 0.84 / Cabinet 0.86）cache 尚未反超——教师本身已高。

### 3.1 固定家具类（6 个）

- **CloseFridge**（0.481/0.88）：目标=关上冰箱门。全场 37 个家具关节里**唯一随 seed 变的是冰箱门铰链**：范围 1.415–1.569 rad（81°–90°），且库轨迹的角度区间 [1.415,1.569] **完全覆盖** eval 区间 [1.438,1.566]——检索可挑到相近门角的轨迹，"抡门关上"动作又对角度不敏感 ⇒ 高分且是权重敏感任务（好 cell 0.88 / 差 cell 0.25）。
- **OpenStandMixerHead**（0.450/0.88）：搅拌机头抬起。**0 个自由物体**——场上连干扰物都没有，纯固定目标；表现同 Fridge 档。
- **OpenDrawer**（0.427/0.88）：**左/右抽屉二值目标**（探测 13 种子 7 左 6 右），抽屉滑轨恒起始于闭合。库 n5 覆盖左 3 右 2 **两侧齐全**；`drawer_obj`（抽屉内物体）X 坐标双峰相距 3.5m 即左右两个抽屉位。**这是权重搜索真正在优化的任务**：视觉权重配对了才能挑中同侧轨迹，配错则 ~50% 挑错侧（错侧必败）——它贡献了全矩阵最大的跨 cell 方差（0.12–0.88）。
- **TurnOnSinkFaucet**（0.211/0.50）：龙头把手恒起始闭合、目标关节不随 seed 变；变的只有台面干扰物（2–4 个）。教师采集期同场景 61/233=**0.26**（n=233，全任务最大样本；准入门场景A 的 0/5 是小样本假象，同门场景B 4/5），cache 均值 0.21 略低、好权重区 0.50≈2×。均值不高的原因：把手小、对末端精度敏感，臂初始 ±4° 抖动足以让部分重放擦肩。
- **OpenCabinet**（0.055/0.25）：指令有"door/doors"两变体（单双门柜之别）——目标柜体随 seed 换，且柜门把手位置随之大变；库 5 条难覆盖 ⇒ 接近死区。
- **SlideDishwasherRack**（0.122/0.25）：**推入/拉出二值目标**（6/7 分布）——方向选错即必败，同 OpenDrawer 机理但目标更难（架子行程长）。

### 3.2 可动物体·类别恒定类（3 个）

- **PickPlaceToasterToCounter**（0.140/0.25）：**PickPlace 族里唯一指令恒定的**——从烤面包机取物类别固定，只有位置/干扰物变 ⇒ 它就是"类别重抽才是死因"的反面对照：同族任务，仅仅因为类别不重抽，成功率高一个数量级。
- **CloseBlenderLid**（0.070/0.38）：盖搅拌机盖，盖子类别恒定但位置变；教师采集期 0.76（n=72）⇒ 差距主要是位置迁移损失。
- **CoffeeSetupMug**（0.038/0.25）：放杯，杯位置变 + 放置目标精度高。

### 3.3 可动物体·类别重抽类（4 个死任务）

统一机理（详见 §4）：物体类别每集从任务池重抽（探测 13 种子出现 7–13 种指令变体），位置沿台面散布 >1.1m（CounterToStove 的 `obj_main` X spread 1.155m 实测）；n=5 库只覆盖 eval 类别的 19%。成功=类别巧合 × 几何巧合的乘积 ≈ 1.2–1.6%。教师采集期同场景 **0.56–0.83**（n=64–89）⇒ 35–70× 的落差全部是 cache 迁移损失，不是任务超纲。

## 4. n=5 库对 eval 的覆盖（抽样物体类任务的死因）

- 库构成：**每任务 5 条全部成功的教师轨迹**（65/65 success=True 亲验；采集池成功率 GR00T 58%、pi05 49%，建库时只取成功集）。
- 四个 PickPlace 任务的类别覆盖（eval 8 个初始状态的物体是否在库中存在）：**6/32 ≈ 19%**。
  - SinkToCounter：库{红薯,番茄,彩椒,桃,牛排}，eval 命中 1/8（桃）；
  - CounterToStove：库{茄子,彩椒,热狗胚,奶酪,烤串}，eval 命中 2/8（奶酪、热狗胚）；
  - CounterToCabinet：库{洗碗刷,罐头,青柠,香蕉,冰块}，eval 命中 **0/8**；
  - DrawerToCounter：库{削皮器,夹子,擀面杖,勺,打蛋器}，eval 命中 3/8。
- 成功与覆盖的交叉（41-cell journal）：DrawerToCounter 的成功 5/7 落在覆盖 idx 上；但 CounterToStove 的 7 次成功全在**未覆盖**的"鸡蛋"上——**类别命中提高碰巧率，但成败的本质是"库轨迹的抓放几何是否恰好扫过 eval 物体的位置"**。
- 教师对照（采集战役同场景实测，2026-08-23 全量重算）：这 4 个任务教师 **0.56–0.83**（n=64–89）⇒ **不是任务超纲，是纯 cache 迁移失败**（35–70× 落差）。

## 5. 对 cache 实验的推论

1. **任务两极化的机理**：固定家具类（Fridge/Drawer/Mixer/Faucet…）目标位置恒定 ⇒ 轨迹重放天然对位（0.75–0.88）；抽样物体类 ⇒ 需要"类别 × 位置"双重巧合（~1.5%）。
2. **权重搜索优化的其实是什么**：跨 cell 方差几乎全部由固定家具类贡献（OpenDrawer 0.12–0.88 最大）——权重配得好=视觉检索能挑中"同侧/同角度"的库轨迹（OpenDrawer 库左 3 右 2 两侧全覆盖，是最典型的可优化任务）。v2 是主载体、rs 辅助、v0/v1 无正贡献（iso 锚点 0.202/0.144/0.019/0.019）。
3. **prompt_emb 的设计差异**：本轮沿 LIBERO 形制关闭了 prompt_emb 检索权重（那边任务内指令恒定）；RoboCasa 的指令在任务内随物体变，理论上 prompt_emb 能帮"对上类别"——但 n=5 覆盖瓶颈在先（19%），类别对上位置也对不上，救不动 PickPlace；记为后续轮次的设计选项而非本轮缺陷。
4. **剔除裁决的依据**（owner 已裁：跑完再弄）：4 个 PickPlace 任务对权重搜索零分辨信号，从搜索指标剔除统计上正当；但在报告里必须定性为"**纯 cache 不可迁移任务**"（教师能做），是方法的失败模式证据，不是坏任务。

## 6. 附件与复现

- 首帧对照页：`pickplace_first_frames.html`；成功数矩阵：`ws_search_matrix.html`（均在本目录）。
- 探测数据：`ws_object_probe.json`（死任务物体类别，13 任务 prompt 全集另见探测日志抢救件）+ `ws_anatomy.json`（4 代表任务的家具 qpos/自由体坐标/机器人基座与臂 qpos，逐种子）。
- 探测方法：env 配方与 eval 完全一致（`gym.make("robocasa/<task>", split=None, obj_instance_split="target", layout_and_style_ids=[(1,1)], camera 512²)`），`reset(seed=k)` 确定性复现采集（base 0）与 eval（base 1,000,000）两族初始状态后直读 MuJoCo 模型（关节 qpos / 自由体位置 / prompt）。⚠ 复现坑：同进程连建 ≥13 个 kitchen env 会 GL 离屏帧缓冲耗竭（`FatalError 0x8cdd`）——每任务独立进程跑。
- teacher 基线：主口径=采集战役 h5 的 `success` 属性逐任务统计（`/data/robocasa365_cache/build_l1s1/groot_tp/<task>/`，2026-08-23 T5b 扩容后 n=64–233，全库 1200 集 / 704 成功）；pi05 侧同法（1539 集 / 704 成功，n=56–397）；`exp/robocasa365/data/{groot_tp,pi05}_gate_180ep.json` 的 n=5 门值仅作历史参考。
