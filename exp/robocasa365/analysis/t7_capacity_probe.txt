The two walls
-------------
1. Host memory bandwidth: one cp1_search scans ~1.9 GB of key vectors
   (4794 entries x 3 vision fields x 32768 dims); 3 concurrent scan streams
   (~22 GB/s) fit the host's DDR budget, 6+ thrash it — more servers past
   S=3-4 slow EVERY search (torch CPU threads pile up: load 33, CPU% high,
   throughput down). Scales with library size: pi05 n5 is 2.8G (+45%/scan),
   n10/n20 ladders will bite harder.
2. WAN path is WiFi: default route = wlx* USB wireless adapter. Measured rx
   8.3 MB/s during T3 — 18 concurrent obs-upload streams hit WiFi airtime
   contention (classic many-stream collapse). 12 streams (T2) stayed healthy.
