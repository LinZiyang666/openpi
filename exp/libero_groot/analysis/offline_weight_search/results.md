# 离线 LOTO 动作距离选权重：能否复现闭环搜出来的模态权重

> 2026-09-13。脚本 `exp/libero_groot/analysis/offline_weight_search.py`，四个库各一份 `offline_weight_search.json`。

## 方法

每条轨迹从库里隔离，用它的每个 entry 去剩余库里检索（同任务、走生产检索栈：逐字段 zscore+tanh 归一化再加权求和，
top-1），取命中 entry 的动作块与 query 自己的动作块做 L2（前 5 步 × 有效维度），对全库 query 取平均。
权重在闭单纯形上按 1/48 步长扫 1,225 个点，平均 L2 最小者胜。归一化参数用各库对应模板里拟合好的 μ/σ。

## 读数

1. **不能复现。** 四个库里闭环赢点都只排在离线榜的 20%–40% 分位；离线最优在 GR00T 两库上一致偏向
   agentview 独大、wrist 几乎为零，闭环两库都要 wrist 占 1/3–5/12。pi0.5 libero_10 甚至方向相反
   （离线要 wrist 0.81，闭环要 agentview 0.56）。
2. **GR00T 库上这个目标几乎没有分辨力**：全网格 L2 跨度只有 0.8–1.3%，连角点都差不多。GR00T 的 16 步动作块在
   同任务近邻之间本来就很像，谁的动作和"自己"更像基本取决于噪声。pi0.5 库有 34–43% 的跨度，目标是有结构的，
   但结构和闭环成功率的结构不是一回事。
3. **为什么不是一回事**：L2 奖励的是"检索到同相位、动作几乎一样的邻居"，这是静态最近邻好坏；闭环成功要的是
   取回的动作块**从当前状态出发能执行下去**且误差不累积成失败——同相位但姿态略偏的动作 L2 很小却会把手臂带偏，
   相位错误但方向对的动作 L2 大却未必失败。wrist 相机对"能不能执行"信息量大（夹爪与物体的相对关系），
   对"动作像不像"信息量小，所以离线目标系统性低估 wrist。
4. GR00T libero_10 是唯一接近的：离线最优的邻格 (4,1,1) 就是闭环榜首，但这更像是这一库的闭环地形本身
   偏 agentview（v0 独占也有 0.18→v0 主导区 0.40–0.45），不是离线目标找到了它。

## 附：J 比例权重（零成本启发）

标 normalizer 时每模态算过 `J = mag_sep + β·intra_spread − λ·sat`（留一轨迹后，同任务 vs 异任务候选的归一化分均值差 +
堆内标准差 − 饱和比例；它是给同一模态挑 normalizer 的排序分）。把三个 J 归一化当权重，对照闭环赢点：
GR00T spatial 0.408/0.341/0.251 vs 0.417/0.333/0.250（一致）；GR00T libero_10 0.450/0.277/0.273 vs 0.500/0.417/0.083（agentview 对）；
π0.5 spatial 0.422/0.303/0.275 vs 0.062/0.500/0.438（错）；π0.5 libero_10 0.422/0.265/0.313 vs 0.562/0.250/0.188（方向对）。
没有数学原理，且 J 的信号项量的是任务间分离，线上检索是任务内比较，轴不对；只能当搜索起点。

## 可以再试的目标（未做）

- 按 remaining（离终点步数）或相位差惩罚，而不是动作 L2：检索到"更靠前/更靠后"的邻居直接计相位误差。
- 任务内信噪比加权：每模态对"正确邻居"（跨轨迹、相位最近）与"错误邻居"的分离度 $d_f$ 和噪声 $\sigma_f$，取 $w_f\propto d_f/\sigma_f^2$。
- 只用成功轨迹的 query，或按 query 后续是否成功加权。
- 把 L2 换成执行后的状态偏差（需要仿真一步），那已经是半闭环了。
